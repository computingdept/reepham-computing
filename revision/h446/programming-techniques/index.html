SECTION 01 · 2.2.1 (a)

Sequence and branching

Sequence executes instructions in order. Each instruction can use the state produced by the previous one. Reordering assignments can change the result.

C#

int price = 7;
int quantity = 3;
int total = price * quantity;
Console.WriteLine(total);

OCR pseudocode

price = 7
quantity = 3
total = price * quantity
print(total)

The output is 21. The multiplication uses the current values of price and quantity.

Branching chooses a path

A Boolean condition decides which instructions run. An if / else if / else chain takes the first matching branch, then skips the rest. Several separate if statements can all run.

C#

int mark = 72;
string grade;
if (mark >= 80)
    grade = "A";
else if (mark >= 60)
    grade = "B";
else
    grade = "C";
Console.WriteLine(grade);

OCR pseudocode

mark = 72
if mark >= 80 then
    grade = "A"
elseif mark >= 60 then
    grade = "B"
else
    grade = "C"
endif
print(grade)

72 fails the first condition and satisfies the second: the output is B. Test the highest threshold first; testing 60 first would also catch 85.

Boundary check: 59 → C, 60 → B, 79 → B, 80 → A. The algorithm assumes marks are valid; input validation is a separate concern.

Conditions and alternatives

Use == for equality and != for inequality. In C#, &&, || and ! mean AND, OR and NOT. OCR uses AND, OR and NOT. Assignment = changes a value; it does not compare values.

For a small set of exact choices, C# switch and OCR switch / case / default / endswitch express multiway branching. For ranges such as marks, an if-chain is usually clearer.

C#

switch (choice)
{
    case "R":
        Console.WriteLine("Read");
        break;
    default:
        Console.WriteLine("Unknown");
        break;
}

OCR pseudocode

switch choice:
    case "R":
        print("Read")
    default:
        print("Unknown")
endswitch

SECTION 02 · 2.2.1 (a)

Iteration and tracing

Iteration repeats instructions. Choose a count-controlled loop when the number of repetitions is known; use a condition-controlled loop when continuation depends on state.

Count-controlled: accumulate a total

C#

int total = 0;
for (int i = 1; i <= 4; i++)
{
    total = total + i;
}
Console.WriteLine(total);

OCR pseudocode

total = 0
for i = 1 to 4
    total = total + i
next i
print(total)
After iterationi usedtotal
Initial state—0
111
223
336
4410

The output is 10. OCR's upper limit is inclusive. The equivalent C# comparison is i <= 4, not i < 4.

Precondition: zero or more repetitions

C#

int remaining = 3;
while (remaining > 0)
{
    Console.WriteLine(remaining);
    remaining--;
}

OCR pseudocode

remaining = 3
while remaining > 0
    print(remaining)
    remaining = remaining - 1
endwhile

Output: 3, 2, 1. If remaining starts at zero, the body never runs. Without the decrement, this example would repeat forever.

Postcondition: at least one repetition

C#

string answer;
do
{
    Console.WriteLine("Type yes");
    answer = Console.ReadLine() ?? "";
} while (answer != "yes");

OCR pseudocode

do
    answer = input("Type yes")
until answer == "yes"
Opposite conditions: C# repeats while the answer is not yes. OCR stops when it is yes. Both read at least once. In the C# example, ?? "" substitutes an empty string if no input is available.

Nested loops

If an outer loop runs 3 times and its inner loop runs 4 times per outer iteration, the inner body runs 12 times. Trace the inner loop afresh for each outer iteration. Check initial values, comparison operators and updates when diagnosing off-by-one errors.

SECTION 03 · 2.2.1 (c)

Global and local variables

Scope is the region where a name is accessible. A local variable belongs to a subroutine or block. Each call normally has its own local values. A global variable can be accessed across subroutines, making it shared state.

Prefer parameters and return values for ordinary data flow: the dependencies are visible. Shared mutable state can make the result depend on which subroutine ran earlier, complicating testing and debugging.

A shared counter and a local increment

C#

using System;
class Program
{
    static int visits = 0;
    static void RecordVisit()
    {
        int increment = 1;
        visits += increment;
    }
    static void Main()
    {
        RecordVisit();
        RecordVisit();
        Console.WriteLine(visits);
    }
}

OCR pseudocode

global visits = 0
procedure recordVisit()
    increment = 1
    visits = visits + increment
endprocedure
recordVisit()
recordVisit()
print(visits)

The output is 2. Each call creates its own local increment; both calls update the same visits variable.

C# distinction: C# has no ordinary global-variable declaration. Here a static class field models shared state for methods in that class. Its accessibility is controlled by the class and access modifiers; it is not automatically accessible everywhere. A variable declared inside Main is local to Main.

Scope is not lifetime

A name can be out of scope even while an associated object still exists. For these simple examples, focus on which method or block may use each name. A local variable declared inside a loop body cannot be used outside that block.

Two separate methods can each have a local variable named total without sharing its value. Avoid confusing names that hide a field: use clear names or explicitly qualify the field when necessary.

SECTION 04 · 2.2.1 (d)

Modularity, functions and procedures

Modularity divides a program into smaller parts with clear responsibilities. For a booking program, reading a request, calculating a charge and displaying a receipt can be separate subroutines.

A cohesive module performs one related task. Clear inputs and outputs reduce coupling between modules. Benefits include reuse, smaller units to test, easier maintenance and division of work. These benefits depend on sensible interfaces: many hidden global dependencies undermine them.

A function returns a result

C#

static int CalculateCost(int tickets, int price)
{
    return tickets * price;
}
// In Main:
int cost = CalculateCost(3, 8);
Console.WriteLine(cost);

OCR pseudocode

function calculateCost(tickets, price)
    return tickets * price
endfunction
cost = calculateCost(3, 8)
print(cost)

The parameters tickets and price receive the arguments 3 and 8. The returned result 24 becomes the caller's cost value. A return hands a value back to the caller; printing only displays it.

A procedure performs an action

C#

static void ShowReceipt(int cost)
{
    Console.WriteLine("Cost: " + cost);
}
// In Main:
ShowReceipt(24);

OCR pseudocode

procedure showReceipt(cost)
    print("Cost: " + str(cost))
endprocedure
showReceipt(24)

C# calls both kinds methods. A method with a result type such as int corresponds to a function; a void method corresponds to a procedure. A procedure can still accept parameters and change state.

Where C# snippets belong: Unless a complete class is shown, put method definitions inside a Program class and the lines marked “In Main” inside static void Main(). Add using System; for Console. The construct-only snippets also belong in Main.

Follow the call

  1. The caller evaluates the argument expressions.
  2. The subroutine receives its parameters and executes its body.
  3. A function returns its result, or a procedure finishes its action.
  4. Execution continues after the call.

For CalculateCost(2 + 1, 8), the first argument evaluates to 3 before the method uses it.

SECTION 05 · 2.2.1 (d)

Passing by value and by reference

A parameter is a name in a subroutine definition; an argument is the value or variable supplied at the call. The passing mechanism determines whether assigning to the parameter can change the caller's variable.

By value: change a copy

C#

static void Increase(int value)
{
    value = value + 1;
}
// In Main:
int score = 10;
Increase(score);
Console.WriteLine(score);

OCR pseudocode

procedure increase(value:byVal)
    value = value + 1
endprocedure
score = 10
increase(score)
print(score)

The output is 10. Inside the call, value becomes 11; score remains 10.

By reference: update the caller's variable

C#

static void Increase(ref int value)
{
    value = value + 1;
}
// In Main:
int score = 10;
Increase(ref score);
Console.WriteLine(score);

OCR pseudocode

procedure increase(value:byRef)
    value = value + 1
endprocedure
score = 10
increase(score)
print(score)

The output is 11. Both names refer to the same variable storage during the call. C# requires ref at both declaration and call; the variable must already be assigned. In OCR notation, the parameter annotation specifies the mechanism.

Reference types are a separate idea

C# normally passes arguments by value. For an array, that copies the reference to the array, not the array contents. Both references reach the same array, so modifying an element is visible to the caller without ref. Reassigning the copied parameter to a new array does not replace the caller's variable.

static void Change(int[] values)
{
    values[0] = 9;          // Changes the shared array
    values = new int[] {7}; // Reassigns only the local parameter
}
// In Main:
int[] numbers = {1};
Change(numbers);
Console.WriteLine(numbers[0]); // 9

Use a return value when a routine's purpose is to calculate a result. Use reference parameters deliberately when updating the caller's variable is part of the interface. Avoid surprising side effects.

SECTION 06 · 2.2.1 (e)

Developing and debugging with an IDE

An integrated development environment brings editing, building, running and debugging into one workspace. For C#, Visual Studio is one example.

FeatureHow it helps
Syntax highlighting and indentationExpose structure and make code easier to read.
Completion and parameter hintsSuggest identifiers and show expected arguments.
Compiler diagnosticsPoint to code that cannot be built, such as missing punctuation or incompatible types.
BreakpointPause execution at a chosen statement to inspect state.
Step into / over / outFollow execution into a call, run the call without entering it, or finish the current call.
Locals and watchesInspect variables and selected expressions as execution progresses.
Call stackShow the active chain of calls that led to the current location.

Recognise the kind of fault

A syntax error breaks language grammar, such as a missing semicolon. A runtime error occurs during execution, such as indexing beyond an array. A logic error lets the program run but produces an incorrect result. A clean build does not prove the algorithm is correct.

Worked debugging example: a missing final term

int total = 0;
for (int i = 1; i < 4; i++)
{
    total += i;
}
Console.WriteLine(total);

The intention is to total 1 through 4, giving 10. The actual output is 6.

  1. Reproduce the error and record expected 10 versus actual 6.
  2. Set a breakpoint on total += i; and watch i and total.
  3. Step through: totals become 1, 3 and 6. When i becomes 4, the condition is false; the body is skipped.
  4. Change i < 4 to i <= 4.
  5. Run again and compare with 10. Check a one-iteration case too, rather than relying only on this example.
Explain the evidence: “The watch showed i reached 4, but the loop condition rejected it” is more useful than “I used the debugger.” Tools reveal state; you still need an expected result and a reasoned diagnosis.

Testing demonstrates a difference between expected and actual behaviour. Debugging locates and repairs its cause. Rerun relevant tests after a fix to check that it has not broken other behaviour.
