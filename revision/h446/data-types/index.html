SECTION 01 · FROM LESSON 001

Data types & unsigned binary

Choose the right data type

1. Choose the type for the purpose

A data type describes the kind of value being stored and the operations that make sense for it. All these values are ultimately represented using bits.

Data typeWhat it storesExample & reason
IntegerA whole number, including zero or a negative value28 students — a count
Real / floating pointA numerical value that can have a fractional part18.5 °C — a measurement
CharacterOne character'A' — a single grade letter
StringA sequence of characters"0042" — an ID whose zeros matter
BooleanTrue or FalseTrue — permission granted
Think aloud: “A phone number contains digits, but I do not add phone numbers together. I choose a string to preserve its leading zero and any + sign.”

Language conventions vary: some languages use a one-character string rather than a separate character type. Floating point has limited precision; it cannot store every real number exactly.

Worked examples

1. Binary → denary

Denary is base 10. Binary is base 2: each place is worth twice the place to its right. For unsigned binary, every place value is positive.

WORKED EXAMPLE 00101101₂ → ?₁₀
1286432168421
00101101
Most significant bit ←→ Least significant bit

32 + 8 + 4 + 1 = 45

Model: Write the place values. Select only the columns containing a 1. Add those values. A 0 contributes nothing.

2. Denary → binary

Convert 74 into an 8-bit unsigned value. Move left to right: if a place value fits into the remainder, write 1 and subtract it; otherwise write 0.

Place value1286432168421
Write01001010
Remainder741010102200

Result: 74₁₀ = 01001010₂. Check: 64 + 8 + 2 = 74. Leading zeros keep the answer at eight bits without changing its unsigned value.

Boundary check: Eight bits give 2⁸ = 256 different patterns, representing unsigned integers from 0 to 255. The largest value is 2⁸ − 1 because zero uses one pattern.

SECTION 02 · FROM LESSON 002

Signed integers

REPRESENTATION 1

Sign magnitude

The leftmost bit is a sign: 0 for positive, 1 for negative. The remaining seven bits store the magnitude.

10000101 = −5: sign 1, magnitude 0000101 = 5.

Eight-bit range: −127 to +127. There are two zero patterns: 00000000 and 10000000.

REPRESENTATION 2

Two’s complement

The most significant bit has a negative place value. For eight bits:

−128, 64, 32, 16, 8, 4, 2, 1

11111011 = −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5.

Eight-bit range: −128 to +127, with one zero pattern.

Same bits, different meaning: 10000101 means 133 unsigned, −5 in sign magnitude, and −123 in two’s complement.
ARITHMETIC RULES

Carry and overflow are different

Binary columns: 0 + 0 = 0; 0 + 1 = 1; 1 + 1 = 10; 1 + 1 + 1 = 11. Write the rightmost result bit and carry the other bit left.

For fixed-width two’s-complement arithmetic, keep eight result bits. A carry beyond bit 8 is discarded. Signed overflow occurs when the mathematical result is outside −128…127. In addition, two same-sign inputs producing an opposite-sign result indicates overflow.

To subtract B from A, add the two’s-complement representation of −B. Do not use ordinary addition of sign-magnitude patterns.

Worked examples

1. Encode −13 in two representations

  1. Write +13 in eight bits: 00001101.
  2. Sign magnitude: retain the seven magnitude bits and set the sign to 1 → 10001101.
  3. Two’s complement: invert all eight bits → 11110010; add 1 → 11110011.
  4. Check: −128 + 64 + 32 + 16 + 2 + 1 = −13.
Invert-and-add-one negates a value in a fixed width. The most negative value (−128 in eight bits) has no positive counterpart in that width.

2. Decode a two’s-complement value

Decode 11100110 using its signed place values.

−128 + 64 + 32 + 4 + 2 = −26.

Check by finding its magnitude: invert → 00011001; add 1 → 00011010 = 26. The original value is negative, so it is −26.

3. Add 23 and 19

   00010111   (+23)
 + 00010011   (+19)
 ----------
   00101010   (+42)

Start from the right: 1 + 1 = 10 (write 0, carry 1); next, 1 + 1 + 1 = 11 (write 1, carry 1); then 1 + 0 + 1 = 10 (write 0, carry 1). Continue carrying left.

Check: 32 + 8 + 2 = 42. The result is in range, so no signed overflow.

4. Subtract 19 from 12

  1. Write 12 as 00001100 and 19 as 00010011.
  2. Negate 19: invert → 11101100, add 1 → 11101101.
  3. Add 12 and −19:
   00001100
 + 11101101
 ----------
   11111001

Decode: −128 + 64 + 32 + 16 + 8 + 1 = −7. Check: 12 − 19 = −7.

5. Spot signed overflow

   01100100   (+100)
 + 00101000   (+40)
 ----------
   10001100   (−116 if decoded)

The mathematical answer is 140, above +127. Two positive inputs produced a negative stored result: signed overflow. There is no carry out, showing why carry out alone is not a signed-overflow test.

Conversely, −1 + 1 produces 1 00000000. Discard the carry: the stored result is zero and there is no signed overflow.

SECTION 03 · FROM LESSON 003

Hexadecimal, shifts & masks

BASE 16

One hex digit = four bits

Hexadecimal uses 0–9 and A–F. A = 10, B = 11, C = 12, D = 13, E = 14 and F = 15.

Place values from right to left are 1, 16, 256, 4096…. Four bits form a nibble; their 16 patterns match the 16 hexadecimal digits.

Hex is a shorter way to write a bit pattern for people. It does not change the value or make the computer store fewer bits.

Denary0123456789101112131415
Hex0123456789ABCDEF
Binary0000000100100011010001010110011110001001101010111100110111101111
LOGICAL SHIFTS

Move bits; insert zeros

Left by k positions multiplies an unsigned value by 2ᵏ only if no significant bits are lost. A fixed byte cannot grow.

Right by k positions divides by 2ᵏ, discarding any remainder. Logical shifts do not preserve the sign of a negative two’s-complement value.

BIT MASKS

Apply a rule to each column

AND: 1 only when both inputs are 1. Mask 0 clears; mask 1 preserves.

OR: 1 when either input is 1. Mask 1 sets; mask 0 preserves.

XOR: 1 when inputs differ. Mask 1 toggles; mask 0 preserves.

Bit numbering: bit 0 is the rightmost (value 1); bit 7 is the leftmost (value 128).

Worked examples

1. Link all three bases

Convert 173₁₀ to hexadecimal: 173 ÷ 16 = 10 remainder 13. Ten is A; thirteen is D. So 173₁₀ = AD₁₆.

Convert each hex digit to four bits: A → 1010; D → 1101. Hence AD₁₆ = 10101101₂.

Check back in denary: (10 × 16) + 13 = 173. Equally, 128 + 32 + 8 + 4 + 1 = 173.

For binary → hex, group from the right in fours. Pad the left group with zeros if needed: 110101₂ → 0011 0101 → 35₁₆.

2. Use hexadecimal place values

2F3₁₆ = (2 × 256) + (15 × 16) + 3 = 755₁₀.

For denary → hex, repeat division by 16 and read remainders backwards: 755 ÷ 16 = 47 remainder 3; 47 ÷ 16 = 2 remainder 15 (F); 2 ÷ 16 = 0 remainder 2. Result: 2F3.

3. Trace logical shifts in a fixed byte

00010110 (22) left 2  → 01011000 (88)
00101101 (45) right 2 → 00001011 (11)
10110000 (176) left 1 → 01100000 (96)

First: 22 × 4 = 88, with no significant bit lost. Second: 45 ÷ 4 = 11 remainder 1, so the stored result is 11. Third: the leftmost 1 is discarded; 352 cannot fit, so the stored value is not 176 × 2.

4. Preserve or clear selected bits with AND

     10110110
AND  00001111
-------------
     00000110

The mask keeps the low nibble and clears the high nibble. Only columns with two 1s produce 1.

To test bit 2, use 00000100. A nonzero AND result means that bit is set. To clear bit 2 instead, use AND with 11111011.

5. Set with OR; toggle with XOR

     10110110             10110110
OR   00001001        XOR  00001111
-------------        -------------
     10111111             10111001

OR sets bits 3 and 0 to 1, preserving the others. XOR flips every low-nibble bit, preserving the high nibble. Applying the same XOR mask twice restores the original value.

SECTION 04 · FROM LESSON 004

Denary → floating point

BINARY FRACTIONS

Place values continue after the point

Integer places      Fractional places
    4  2  1    .     ½  ¼  ⅛  ¹⁄₁₆  …

6.5 = 4 + 2 + ½ = 110.1₂. For 0.375, select ¼ + ⅛: 0.011₂. Another method: repeatedly multiply the fraction by 2, recording each integer part in order. Stop when the remaining fraction is zero.

TWO FIELDS

Value = mantissa × 2ᵉˣᵖᵒⁿᵉⁿᵗ

Mantissa weights: −1 | ½  ¼  ⅛  ¹⁄₁₆  ¹⁄₃₂  ¹⁄₆₄  ¹⁄₁₂₈
Exponent weights: −8   4   2   1

The mantissa’s binary point is immediately after its sign bit; it is implied, not stored. The exponent is a signed integer from −8 to +7. There is no separate sign bit outside these fields and no exponent bias in this format.

NORMALISATION

The first two mantissa bits must differ

A normalised positive mantissa starts 01; a negative mantissa starts 10. Leading 00 or 11 means redundant sign bits remain. Shift the mantissa left and decrease the exponent by the same number of places, preserving the value.

Normalisation makes full use of the significant bits available. Extra mantissa bits improve precision; extra exponent bits increase range. Zero is a special case: use all-zero fields.

Worked examples

1. Positive value: 6.5

6.5 = 110.1₂ = 0.1101₂ × 2³
Mantissa: 01101000    Exponent: 0011
Stored:   01101000 0011

Move the binary point three places left to make the mantissa 0.1101. Pad on the right to fill eight bits including the sign. Check: 0.8125 × 8 = 6.5.

2. A small fraction: 0.15625

0.15625 = ⅛ + ¹⁄₃₂ = 0.00101₂
        = 0.101₂ × 2⁻²
Mantissa: 01010000    Exponent: 1110
Stored:   01010000 1110

Move the point two places right, so the exponent is −2. Encode −2 in four-bit two’s complement: +2 is 0010; invert and add 1 → 1110.

3. Negative value: −6.5

Positive mantissa:   01101000
Invert:              10010111
Add 1:               10011000
Stored:              10011000 0011

Negate the mantissa using two’s complement; keep the exponent 3. The leading bits are 10, so the result is normalised. Check: −0.8125 × 8 = −6.5.

4. Normalise an existing pattern

00011010 0101   exponent 5
00110100 0100   exponent 4
01101000 0011   exponent 3

Two left shifts multiply the mantissa by 4; reducing the exponent by 2 divides the scale by 4. Both patterns represent 6.5. Stop as soon as the first two bits differ.

5. Check after negating: −0.5

−0.5 initially: 11000000 0000
Normalised:    10000000 1111

11000000 represents −0.5 but starts 11. Shift left once to get a mantissa of −1 and reduce the exponent to −1. Check: −1 × ½ = −0.5. Negating a normalised positive mantissa does not always leave a normalised negative mantissa.

SECTION 05 · FROM LESSON 005

Floating point → denary

Split → evaluate → scale

8-bit mantissa: −1 | ½  ¼  ⅛  ¹⁄₁₆  ¹⁄₃₂  ¹⁄₆₄  ¹⁄₁₂₈
4-bit exponent: −8   4   2   1
Value = mantissa × 2ᴱ
  1. Split the pattern at the stated field boundary.
  2. Add the mantissa weights whose bits are 1. Include −1 if the sign bit is 1.
  3. Decode the exponent as a signed integer.
  4. Multiply by 2ᴱ. For a negative exponent, divide by the corresponding power of two.

Two signs with different jobs

The mantissa determines the sign of the number. The exponent determines its scale. A negative exponent does not make the value negative: 2⁻² = ¼.

This is a signed fractional mantissa, not sign magnitude. There is no biased exponent in these questions.

Normalisation, precision and range

Nonzero normalised mantissas begin 01 (positive) or 10 (negative). Patterns beginning 00 or 11 can still be decoded; normalisation preserves their value. Zero is a special case.

More mantissa bits allow more significant detail: greater precision. More exponent bits allow a wider range of scales. At a fixed total width, allocating extra bits to one field leaves fewer for the other.

Worked examples

1. Positive mantissa and exponent

Mantissa 01011000 = 0.6875
Exponent 0011 = 3
Value = 0.6875 × 2^(3) = 5.5

½ + ⅛ + ¹⁄₁₆ = 0.6875. The exponent is 3, so multiply by 8.

2. A negative mantissa

Mantissa 10110000 = -0.625
Exponent 0010 = 2
Value = -0.625 × 2^(2) = -2.5

−1 + ¼ + ⅛ = −0.625. The leading 1 has weight −1; it is not a separate minus sign in front of the remaining bits.

3. A negative exponent

Mantissa 01100000 = 0.75
Exponent 1110 = -2
Value = 0.75 × 2^(-2) = 0.1875

1110 = −8 + 4 + 2 = −2. Divide 0.75 by 4. The answer remains positive.

4. Both fields are negative

Mantissa 10100000 = -0.75
Exponent 1111 = -1
Value = -0.75 × 2^(-1) = -0.375

The mantissa is −1 + ¼ = −0.75; the exponent −1 means halve it.

5. Decode first, then check normalisation

Mantissa 00011010 = 0.203125
Exponent 0101 = 5
Value = 0.203125 × 2^(5) = 6.5

The mantissa begins 00, so it is not normalised. Two left shifts give 01101000 0011; this also represents 6.5. Do not reject a pattern merely because it is not normalised.

SECTION 06 · FROM LESSON 006

Floating-point addition

Align → add → normalise

Six-bit mantissa weights: −1 | ½  ¼  ⅛  ¹⁄₁₆  ¹⁄₃₂
Four-bit exponent weights: −8   4   2   1
  1. Choose the larger exponent.
  2. For every increase of 1 in the smaller exponent, shift that mantissa right once. Repeat the sign bit on the left.
  3. Add the aligned mantissas. Use a temporary extra sign bit so the working sum cannot wrap into the wrong sign.
  4. Normalise the result and write the requested mantissa and exponent widths.

Sign-preserving shifts

An arithmetic right shift repeats the sign bit: 0 for positive values, 1 for negative values. Lesson 003’s logical shift always inserted 0, so it is not suitable for aligning negative mantissas.

Keep extra low-order working bits if a shift would discard a nonzero bit. These guard bits protect precision during calculation; they are not extra bits in the final stored format.

Keep value and scale in balance

If the sum is outside the mantissa range −1 to less than +1, halve the mantissa and increase the exponent. If it has redundant leading sign bits, shift left and decrease the exponent. Nonzero normalised mantissas begin 01 or 10.

For a six-bit mantissa, a temporary seven-bit sum keeps FIVE fractional positions: its weights are −2, 1, ½, ¼, ⅛, ¹⁄₁₆, ¹⁄₃₂. This wider working sum is not a seven-bit stored mantissa.

Check the exponent fits −8…7. Exponent overflow means the value is too large for this format; insufficient mantissa precision is a different problem.

Worked examples

1. Different exponents: 5 + 1.5

Use common exponent 3 (0011). Shift the smaller-scale mantissa right, repeating its sign bit.

Aligned mantissas: 010100 and 000110
Temporary extra sign bit, same fractional places:
   0010100
 + 0000110
 = 0011010

The unnormalised sum is 26/32 × 23. Normalise and return to the requested field widths.

Final: 011010 0011

Denary check: 5 + (1.5) = 6.5.

The second exponent rises from 1 to 3: two right shifts turn 011000 into 000110. The sum already begins 01.

2. Rescale the sum: 6 + 5

Use common exponent 3 (0011). Shift the smaller-scale mantissa right, repeating its sign bit.

Aligned mantissas: 011000 and 010100
Temporary extra sign bit, same fractional places:
   0011000
 + 0010100
 = 0101100

The unnormalised sum is 44/32 × 23. Normalise and return to the requested field widths.

Final: 010110 0100

Denary check: 6 + (5) = 11.

The working sum is 1.375 × 2³. Halve it to 0.6875 and increase the exponent to 4. This stores 11.

3. A negative operand: −5 + 3

Use common exponent 3 (0011). Shift the smaller-scale mantissa right, repeating its sign bit.

Aligned mantissas: 101100 and 001100
Temporary extra sign bit, same fractional places:
   1101100
 + 0001100
 = 1111000

The unnormalised sum is -8/32 × 23. Normalise and return to the requested field widths.

Final: 100000 0001

Denary check: -5 + (3) = -2.

The aligned sum is −0.25 × 2³. Shift left twice and decrease exponent 3 to 1 to obtain −1 × 2¹ = −2.

4. Align a negative mantissa: −3 + (−2)

Use common exponent 2 (0010). Shift the smaller-scale mantissa right, repeating its sign bit.

Aligned mantissas: 101000 and 110000
Temporary extra sign bit, same fractional places:
   1101000
 + 1110000
 = 1011000

The unnormalised sum is -40/32 × 22. Normalise and return to the requested field widths.

Final: 101100 0011

Denary check: -3 + (-2) = -5.

Align −2 by changing 100000 to 110000 and exponent 1 to 2. The sum −1.25 must be halved while the exponent rises to 3.

5. Precision loss

In 6+4 format, 32 is 010000 0110 and 0.5 is 010000 0000. Aligning the latter to exponent 6 needs six right shifts. Without guard bits, its 1 is discarded.

The exact answer is 32.5. At exponent 6, adjacent representable values differ by 2, so 32.5 cannot be stored exactly with this mantissa. Keep working precision, then apply the rounding or truncation rule specified by the question. Normalisation cannot restore lost bits.

SECTION 07 · FROM LESSON 007

Floating-point subtraction

A − B = A + (−B)

  1. Choose the larger exponent and align mantissas using arithmetic right shifts.
  2. Keep any needed guard bits. Sign-extend both aligned mantissas to a wider working width.
  3. Negate the SECOND mantissa at that width: invert every working bit and add 1.
  4. Add, then normalise the difference and return to the requested field widths.

Do not negate the exponent: it specifies scale. Subtracting a negative value adds its positive counterpart.

Why use extra working bits?

A six-bit mantissa has five fractional positions. A temporary extra sign bit widens the working range without moving those fractional positions. If alignment would discard a nonzero bit, append guard bits on the right before shifting.

For example, shifting 010010 right twice gives 000100.10 when two guard positions are shown: keeping the fractional tail avoids changing 2.25 to 2. This lesson’s worked examples retain only as many guard positions as needed for an exact answer.

Cancellation, zero and range

Subtracting similar values can leave a small difference. Shift left to remove redundant sign bits and reduce the exponent by the same amount. Stop when the first two mantissa bits differ: 01 positive, 10 negative.

Equal operands give zero: use 000000 0000; do not keep shifting. If a nonzero normalised result requires an exponent below −8, it underflows this format. A required exponent above +7 overflows it.

Worked examples

1. Positive difference: 5 − 1.5

Common exponent: 3 (0011). Align both mantissas with sign-preserving right shifts. Keep 0 extra low-order guard bit(s), and one extra leading sign bit. The working binary point stays before the 5 fractional bits.

Aligned A:          0010100
Aligned B:          0000110
Invert B:           1111001
Add 1 to negate B:  1111010
A + (−B):           0001110

The working difference is 14/32 × 23. Normalise and return to the requested field widths.

Final: 011100 0010

Denary check: 5 − (1.5) = 3.5.

The result 3.5 needs one left shift and exponent 3 → 2.

2. Negative difference: 1.5 − 5

Common exponent: 3 (0011). Align both mantissas with sign-preserving right shifts. Keep 0 extra low-order guard bit(s), and one extra leading sign bit. The working binary point stays before the 5 fractional bits.

Aligned A:          0000110
Aligned B:          0010100
Invert B:           1101011
Add 1 to negate B:  1101100
A + (−B):           1110010

The working difference is -14/32 × 23. Normalise and return to the requested field widths.

Final: 100100 0010

Denary check: 1.5 − (5) = -3.5.

Preserve the original operand order. The result is −3.5, not +3.5.

3. Subtract a negative: 5 − (−1.5)

Common exponent: 3 (0011). Align both mantissas with sign-preserving right shifts. Keep 0 extra low-order guard bit(s), and one extra leading sign bit. The working binary point stays before the 5 fractional bits.

Aligned A:          0010100
Aligned B:          1111010
Invert B:           0000101
Add 1 to negate B:  0000110
A + (−B):           0011010

The working difference is 26/32 × 23. Normalise and return to the requested field widths.

Final: 011010 0011

Denary check: 5 − (-1.5) = 6.5.

Negating the aligned negative second mantissa produces a positive addend.

4. Cancellation: 6.5 − 6

Common exponent: 3 (0011). Align both mantissas with sign-preserving right shifts. Keep 0 extra low-order guard bit(s), and one extra leading sign bit. The working binary point stays before the 5 fractional bits.

Aligned A:          0011010
Aligned B:          0011000
Invert B:           1100111
Add 1 to negate B:  1101000
A + (−B):           0000010

The working difference is 2/32 × 23. Normalise and return to the requested field widths.

Final: 010000 0000

Denary check: 6.5 − (6) = 0.5.

The difference is 0.5. Three left shifts remove redundant zeros and reduce exponent 3 to 0.

5. Equal operands

Common exponent: 3 (0011). Align both mantissas with sign-preserving right shifts. Keep 0 extra low-order guard bit(s), and one extra leading sign bit. The working binary point stays before the 5 fractional bits.

Aligned A:          0011000
Aligned B:          0011000
Invert B:           1100111
Add 1 to negate B:  1101000
A + (−B):           0000000

The working difference is 0/32 × 23. Normalise and return to the requested field widths.

Final: 000000 0000

Denary check: 6 − (6) = 0.

The all-zero difference has no leading 01 or 10. Recognise zero and stop. Discard any carry beyond the temporary working width.

SECTION 08 · FROM LESSON 008

Character sets

Characters need agreed codes

A character set defines characters and their assigned codes. An encoding specifies how those codes are represented in bytes. Sender and receiver must agree how to interpret the bytes.

Standard ASCII uses seven-bit codes: 2⁷ = 128 possibilities, including letters, digits, punctuation and control characters such as line feed. Eight-bit extensions provide 256 codes but different extensions can assign different characters.

Unicode and its encodings

Unicode assigns code points to characters from many writing systems and to symbols. Its first 128 code points match ASCII. Unicode is not simply “16 bits per character”.

UTF-8 uses 1–4 bytes per code point; ASCII characters use one byte with the same code value. UTF-16 uses one or two 16-bit code units per code point. Use the encoding and assumptions stated in a storage question.

A displayed character can sometimes combine multiple code points. Our storage exercises explicitly give the number of code points and their byte sizes.

Useful ASCII anchors

'A' = 65    'Z' = 90
'a' = 97    'z' = 122
'0' = 48    '9' = 57
space = 32

Letters and digits are consecutive within these ranges. A lowercase Latin letter is 32 codes above its uppercase partner. The character '7' has code 55; the integer 7 has numeric value 7.

Worked examples

1. Encode a short word

Given A = 65, B = 66. Standard seven-bit codes are A = 1000001 and B = 1000010. Stored in eight-bit bytes, add a leading zero:

AB → 01000001 01000010

The added zero does not expand the standard ASCII character repertoire.

2. Character versus quantity

Character '7': 48 + 7 = 55 → 00110111
Integer 7:                  00000111

The patterns differ because one encodes a text symbol and the other a numeric quantity.

3. Use a code range

To test for an uppercase ASCII letter, its code must satisfy 65 ≤ code ≤ 90. Both conditions must hold, so use AND.

code ≥ 65 AND code ≤ 90

For lowercase c, code = 97 + 2 = 99. Its uppercase partner C has code 99 − 32 = 67. This offset rule is for ASCII Latin letters, not a universal rule for all Unicode text.

4. Choose an encoding

An international messaging app must support English, Greek and Chinese text. Standard ASCII cannot represent all these characters. Unicode provides the repertoire; UTF-8 is one encoding that can store it.

Both ends must interpret the bytes using the same encoding. A larger repertoire alone does not guarantee correct decoding.

5. Calculate storage from stated widths

A UTF-8 message contains 10 ASCII code points and 2 euro-sign code points. Each ASCII code point uses 1 byte and each euro sign uses 3 bytes. Ignore metadata.

(10 × 1) + (2 × 3) = 16 bytes
16 × 8 = 128 bits

Count the stated byte widths, not a blanket number of bits per visible character.
