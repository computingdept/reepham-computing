QUESTION 1 · TEACHER MODEL ANSWER

Explain the strategy

Split the list repeatedly into smaller parts until single items remain. Merge sorted parts into larger sorted lists until the whole list is sorted.
QUESTION 2 · TEACHER MODEL ANSWER

Base case

A single item has no other item that could be in the wrong relative order. The low < high condition is false when low == high.

QUESTION 5 · TEACHER MODEL ANSWER

Merge two sorted lists

2 vs 1: take 1
2 vs 4: take 2
5 vs 4: take 4
5 vs 8: take 5
9 vs 8: take 8
Right exhausted: copy 9
Result: [1, 2, 4, 5, 8, 9]
QUESTION 6 · TEACHER MODEL ANSWER

Unsorted inputs

Only the next available value from each side is compared, so each must be that side's smallest remaining value. Example: merging unsorted [5, 2] with [3, 4] by this rule produces [3, 4, 5, 2], which is not sorted.
QUESTION 7 · TEACHER MODEL ANSWER

Read the pointers

left: next unread index in the left half.
right: next unread index in the right half.
out: next output index in temp.
Only the pointer for the copied side advances; out advances after every copy.
QUESTION 8 · TEACHER MODEL ANSWER

Find the error

The main merge loop stops as soon as either half is exhausted. Values on the other side would not be copied. For [2, 6] and [1, 7], 7 would be omitted from the new merged result; copying temp back may insert a stale/unset value.
QUESTION 9 · TEACHER MODEL ANSWER

Duplicates · extension

Take 1 from the right.
Take 2 from the left.
Compare 4 and 4: take left 4.
Compare 4 and 4: take left 4 again.
Left exhausted: copy right 4, then 6.
Result: [1, 2, 4, 4, 4, 6].
<= takes the left item first on equality, preserving their relative order across the halves.
QUESTION 10 · TEACHER MODEL ANSWER

Descending order · extension

Change values[left] <= values[right] to values[left] >= values[right].
Splitting, base case, pointer updates, leftover copying and copying back stay the same.
Recursive merges now produce descending halves.
Output: [8, 7, 6, 5, 4, 3, 2, 1].
