Lesson 062 · Thinking Procedurally: Ordered Subtasks

By the end you can…
  • Identify the separate components of a problem: validation, stock check, updating records and confirming a result.
  • Determine necessary order from dependencies. Do not send success or deduct stock before validation.
  • Decompose large operations into subprocedures, each with clear responsibility; update-related steps may need a single transaction to maintain consistency.

I DO · MODEL

Put steps in order to process an exam result securely: check identity, find result, return data.

Identity check → authorised lookup → return only permitted result.
WORKED EXPLANATION

Explain the decision

If lookup occurs before checking authorisation, data can be exposed through insecure responses.

WE DO · NEW SCENARIO

A checkout program has steps deduct stock, check payment, pack goods. Choose order and justify.

Validate order → authorise payment → atomically confirm order and stock → pack or dispatch.
WORKED EXPLANATION

Explain the decision

Payment and stock operations need failure handling; no dispatch before a confirmed order.
