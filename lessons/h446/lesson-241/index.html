By the end you can…
  • Decompose a real-world problem into subprocedures
  • Order tasks according to their dependencies
  • Explain why state updates must succeed before confirmation

NEW LEARNING · EXAMPLE FIRST

Predict the program's next step

// Ticket-booking stages
// ValidateRequest → CheckCapacity
// → SaveBooking → SendConfirmation
// Each stage uses the previous stage's result.
STEP 1 OF 3

Decompose the task

Separate the problem into input validation, checking availability, updating the record and notifying the user.

STEP 2 OF 3

Identify dependencies

No booking should be saved until seats are available; no confirmation should be sent before a successful save.

STEP 3 OF 3

Make smaller operations reusable

ValidateRequest and SendConfirmation can become independently testable subprocedures.

I DO · MODEL

Put password-reset stages in a safe order.

Identify account → Issue token → Verify token
→ Save new password
STEP 1 OF 3

Predict first

First identify the account and create a single-use reset token.

STEP 2 OF 3

Model the reasoning

Check the token before accepting a new password.

STEP 3 OF 3

Model the reasoning

Save the change successfully before confirming to the user.

WE DO · DIFFERENT GUIDED EXAMPLE

Order steps for borrowing a library book online.

Find book → Check available
→ Record loan → Update availability
→ Confirm
STEP 1 OF 2

Predict first

Identify the book and verify availability before trying to record a loan.

STEP 2 OF 2

Model the reasoning

Store the loan and change availability, then confirm only if those actions succeed.

Core · 6 marks · QUESTION 2 OF 3

Design four named subprocedures for booking a classroom and give two key ordering requirements.

MODEL ANSWER

[6] ValidateInput [1], CheckRoomAvailable [1], SaveBooking [1], SendConfirmation [1]; check room before save [1], save before confirm [1].

Stretch · 6 marks · QUESTION 3 OF 3

A booking code subtracts seats from a local int parameter but never updates the central system. Identify three problems and three remedies.

MODEL ANSWER

[6] Parameter is a copy [1], central count unchanged [1], another user could book same seats [1]; update stored capacity [1], use an atomic save/check [1], confirm only after successful save [1].

True or false?

A booking confirmation can safely be sent before the record is saved.

Model answer

False. The save might fail, leaving an unconfirmed booking in reality despite the message.
