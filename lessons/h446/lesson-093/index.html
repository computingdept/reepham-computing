Lesson 093 · Von Neumann and Harvard Architectures

By the end you can…
  • Von Neumann stores programs and their data in a common memory/address space, so instruction fetches and data transfers may contend for shared resources.
  • Harvard architecture separates instruction and data pathways, potentially allowing simultaneous instruction fetch and data access.
  • Modern systems often use unified main memory but separate instruction/data caches; the classification is a model of design trade-offs, not a universal speed ranking.

I DO · WORKED MODEL

Explain one potential bottleneck of simple Von Neumann design.

MODEL EXPLANATION

Explain the mechanism

Instruction and data transfers share memory/bus resources, so competing accesses can wait.

Describe the shared resource and its effect, not claim all Von Neumann machines are slow.

WE DO · DIFFERENT QUESTION

A controller uses distinct code ROM and data RAM accessed via separate pathways. Which model?

MODEL EXPLANATION

Explain the mechanism

Harvard-style separation; fetch instruction and access data paths may operate in parallel.

It differs from a single shared path even when control logic is the same CPU.
