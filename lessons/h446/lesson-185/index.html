Insertion sort: trace and implement

By the end, you can…
  • Identify the sorted prefix
  • Shift values to make space for a key

Key vocabulary for today

keysorted prefixshiftin-placestable
NEW LEARNING · CODE FIRST

Read the code; predict its effect

int[] a = { 3, 7, 2, 5 };
for (int i = 1; i < a.Length; i++)
{
    int key = a[i], j = i - 1;
    while (j >= 0 && a[j] > key)
    {
        a[j + 1] = a[j];
        j--;
    }
    a[j + 1] = key;
}
STEP 1 OF 3

One key at a time

The prefix to the left of i is already sorted; take a[i] as the key.

STEP 2 OF 3

Make room

Shift larger values in the sorted prefix one position to the right.

STEP 3 OF 3

Insert the key

Place it at j+1; the sorted prefix grows by one element.

I DO · MODEL

Insert key 1 into the sorted prefix [4,8] of [4,8,1,6].

STEP 1 OF 2

Predict first

Identify the shifts needed.

STEP 2 OF 2

Model solution

Shift 8 then 4 to the right and insert 1 at index 0 → [1,4,8,6].

WE DO · GUIDED

Insert key 5 into the sorted prefix [2,9] of [2,9,5,7].

STEP 1 OF 2

Predict first

Which value must move first?

STEP 2 OF 2

Model solution

9 moves one index right; 2 stays. Insert 5 at index 1 → [2,5,9,7].

Foundation · 1 OF 3

Insert key 3 into [2,6,3,8], assuming [2,6] is sorted.

WORKED ANSWER

Shift 6, then insert 3 → [2,3,6,8].

Core · 2 OF 3

Trace insertion sort fully on [5,1,4].

WORKED ANSWER

After key 1 → [1,5,4]; after key 4 → [1,4,5].

Stretch · 3 OF 3

Explain why insertion sort is efficient on almost-sorted input.

WORKED ANSWER

Few values need shifting, so its best-case time is O(n), though worst case is O(n²).

True or false?

Insertion sort always swaps each element with its neighbour.

MODEL ANSWER

False. It commonly shifts larger values and places the key in the gap.
