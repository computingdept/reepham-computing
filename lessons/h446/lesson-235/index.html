NEW LEARNING · EXAMPLE FIRST

Study the worked scenario

static bool ValidMark(int mark)
    => mark >= 0 && mark <= 100;
// 0 and 100 are valid boundaries.
// -1 and 101 are erroneous.
STEP 1 OF 3

State the valid range

The specification permits whole-number marks from 0 through 100 inclusive.

STEP 2 OF 3

Choose targeted tests

Normal value 50; valid boundaries 0 and 100; invalid just beyond boundaries −1 and 101.

STEP 3 OF 3

Write expected results

A useful test log records input, expected outcome and actual outcome; a mismatch is evidence of a fault.

I DO · TEACHER MODEL

Design tests for a password length from 8 through 20 characters inclusive.

static bool ValidLength(int n)
    => n >= 8 && n <= 20;
STEP 1 OF 2

Predict first

Test just below and at the lower limit: 7 rejected, 8 accepted.

STEP 2 OF 2

Model and explain

Also test a normal 14, upper boundary 20, and 21 rejected.

WE DO · DIFFERENT GUIDED PROBLEM

Choose boundary and invalid tests for a class size of 1–30 inclusive.

static bool ValidSize(int n)
    => n >= 1 && n <= 30;
STEP 1 OF 2

Predict first

Lower boundary 1 is accepted while 0 is invalid.

STEP 2 OF 2

Model and explain

Upper boundary 30 is accepted while 31 is invalid; 16 is a representative normal value.

True or false?

Testing only typical valid inputs proves that validation rejects out-of-range values.

Model answer

False. Erroneous and boundary-adjacent tests are also needed.
