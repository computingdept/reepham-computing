NEW LEARNING · EXAMPLE FIRST

Study the worked scenario

static bool ValidMark(int mark)
    => mark >= 0 && mark <= 100;
// 0 and 100 are valid boundaries.
// -1 and 101 are erroneous.
STEP 1 OF 3

State the valid range

The specification permits whole-number marks from 0 through 100 inclusive.

STEP 2 OF 3

Choose targeted tests

Normal value 50; valid boundaries 0 and 100; invalid just beyond boundaries −1 and 101.

STEP 3 OF 3

Write expected results

A useful test log records input, expected outcome and actual outcome; a mismatch is evidence of a fault.

EXAM QUESTION 1 OF 4 · 6 MARKS · 6 MINUTES

A school is teaching students to debug their JavaScript programming projects in an integrated development environment (IDE). Identify three different IDE features that help find or diagnose faults. For each feature, describe how a developer would use it while debugging. [6]

OCR H446/02 · June 2025 · Q6(a) · RHS exam-style scenario

MODEL ANSWER · 6 MARKS

Breakpoints pause execution at a chosen line for state inspection. Step-through executes one statement or step at a time to see control flow. Variable watch displays current variables/array values as execution progresses. Error diagnostics locate syntax or runtime errors and provide messages. Any three suitable distinct debug tools accepted.

Marking: For each of three different debugging facilities, award 1 for identifying a genuine feature and 1 for a connected description of its debugging use (6 marks maximum). Do not credit code formatting or autocomplete as debugging features.

EXAM QUESTION 2 OF 4 · 4 MARKS · 4 MINUTES

For a test, numbers = [4, 2, 4, 4, 2, 7] should produce distinct = [4, 2, 7], counts = [3, 2, 1].

GIVEN INFORMATION

A wildlife centre has written an original algorithm to count occurrences of integers in a list. It uses two parallel output arrays: distinct contains each unique integer and counts stores its frequency. Four numbered lines contain a logical error. Identify each wrong line and give a corrected complete line. [4]

01 function countOccurrences(numbers)
02   distinct = []
03   counts = []
04   size = numbers.length
05   for i = 0 to size
06     target = numbers[i]
07     match = -1
08     for j = 0 to distinct.length - 1
09       if distinct[j] != target then
10         match = j
11       endif
12     next j
13     if match == -1 then
14       distinct.append(target)
15       counts.append(0)
16     else
17       counts[match] = counts[match] - 1
18     endif
19   next i
20   return distinct, counts
21 endfunction

OCR H446/02 · June 2025 · Q6(d) · RHS exam-style scenario

MODEL ANSWER · 4 MARKS

Line 05: for i = 0 to size - 1 Line 09: if distinct[j] == target then Line 15: counts.append(1) Line 17: counts[match] = counts[match] + 1

Marking: Four marks: one for each correct combination of the original line number and corrected line (05, 09, 15, 17). Other logically equivalent changes can be considered only if they correctly repair the stated algorithm; four separate fixes are required. This is a newly written four-error challenge, not OCR's source code.

RHS ADDITIONAL PRACTICE · QUESTION 4 OF 4 · 2 MARKS · 2 MINUTES

A debugger is paused just before counts[match] is updated. Explain how a watch window could help check whether the frequency-counting algorithm works. [2]

RHS original follow-on question · linked to this lesson's exam practice

MODEL ANSWER · 2 MARKS

Marking: One mark for identifying appropriate variables to inspect; one for checking their changes against the expected count.

TERM 5 OF 5

regression

New change breaks previously working behaviour.

True or false?

Testing only typical valid inputs proves that validation rejects out-of-range values.

Model answer

False. Erroneous and boundary-adjacent tests are also needed.
