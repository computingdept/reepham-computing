NEW LEARNING · CODE FIRST

Compare the structure of the code

using System;
using System.Linq;
// Procedural: standalone function
int Double(int x) => x*2;
// Object-oriented: state + method
var account = new Account(10);
account.Deposit(5);
// Functional-style transformation
int[] values = {2,3};
var doubled = values.Select(x => x*2).ToArray();
Console.WriteLine(Double(4)); // 8
class Account {
 public int Balance {get;private set;}
 public Account(int balance){Balance=balance;}
 public void Deposit(int amount){Balance+=amount;}
}
STEP 1 OF 3

Procedural

Instructions and procedures operate on arguments or shared data. A function can be reused independently.

STEP 2 OF 3

Object-oriented

The Account object combines state (Balance) and behaviour (Deposit). With inheritance, a subclass can reuse and specialise a class. A virtual method overridden in a derived class supports polymorphism: the actual object decides which implementation runs.

STEP 3 OF 3

Functional style

Values are transformed using expressions/functions, often emphasising avoiding mutation of existing input data.

Classify a function Square(x) that returns x*x without storing object state.

int Square(int x) => x*x;
Console.WriteLine(Square(3));
STEP 1 OF 2

Predict

It is procedural when used as a standalone function in a procedural programme.

STEP 2 OF 2

Model response

Square(3) returns 9; it does not change object state. C# can use more than one paradigm.

I DO · YEAR 13 TRANSFER

Override versus method hiding: what changes?

using System;
BaseMessage a = new EmailMessage();
BaseMessage b = new TextMessage();
Console.WriteLine(a.Label()); // ?
Console.WriteLine(b.Label()); // ?

class BaseMessage {
  public virtual string Label() => "Base";
}
class EmailMessage : BaseMessage {
  public override string Label() => "Email";
}
class TextMessage : BaseMessage {
  public override string Label() => "Text";
}
STEP 1 OF 3 · INHERITANCE

Follow the declared and actual types

Both variables are declared as BaseMessage. Their actual objects are EmailMessage and TextMessage, each inheriting from the base class.

STEP 2 OF 3 · OVERRIDE

Why is virtual important?

The base method is virtual and both derived classes override it. The language dispatches to the actual object's implementation.

STEP 3 OF 3 · VERIFY

Output and design consequence

Outputs Email then Text. The caller can add another derived message class without writing separate type-checking branches.

STEP 2 OF 2

WE DO · HIGHER CHALLENGE

Does a new method behave like an override?

using System;
BaseReport report = new ShortReport();
Console.WriteLine(report.Title());

class BaseReport {
  public string Title() => "Base";
}
class ShortReport : BaseReport {
  public new string Title() => "Short";
}
STEP 1 OF 3 · PREDICT

What prints?

Track the declared type of report and the keyword used on Title().

STEP 2 OF 3 · EXPLAIN

There is no virtual dispatch

new hides the base method; it does not override it. Calls through a BaseReport reference bind to the base method here.

STEP 3 OF 3 · REPAIR

Output and correction

The output is Base. Make BaseReport.Title() virtual, and mark ShortReport.Title() override; then the same base-typed call outputs Short.

Stretch · 6 marks · QUESTION 3 OF 3

Explain why `values.Select(x=>x*2)` can be considered functional-style programming, and one limitation of labelling C# purely functional.

MODEL ANSWER

[6] Applies a function to each element [2], returns transformed values [1], can avoid mutating original list [1]; C# also supports procedural code and mutable objects [1], so language/paradigm are not identical [1].
