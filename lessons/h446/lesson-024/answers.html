Complete C# solution

Teacher live-codes the four chunks in I Do. Use .NET Fiddle or your usual IDE. Expected outputs: 5, 0, 7, -1.

using System;

public class Program
{
    static int BinarySearch(int[] data, int target)
    {
        int low = 0;
        int high = data.Length - 1;

        while (low <= high)
        {
            int mid = low + (high - low) / 2;

            if (data[mid] == target)
                return mid;
            else if (data[mid] < target)
                low = mid + 1;
            else
                high = mid - 1;
        }

        return -1;
    }

    public static void Main()
    {
        int[] data = { 4, 9, 13, 19, 26, 35, 42, 57 };
        Console.WriteLine(BinarySearch(data, 35)); // 5
        Console.WriteLine(BinarySearch(data, 4));  // 0
        Console.WriteLine(BinarySearch(data, 57)); // 7
        Console.WriteLine(BinarySearch(data, 20)); // -1
    }
}

Checks for understanding — expected answers

  • Do Now: index 0; linear = sequential, binary = halves sorted range; numbers[3] = 18; unsorted values invalidate discarding a half.
  • Trace 13: (low 0, high 7, mid 3, value 18) → (0,2,1,7) → (2,2,2,12); low becomes 3 so return -1.
  • Bug: midpoint less than target means increase low, not decrease high.
  • Hinge answer B: low = 4, high = 6. Re-model if a meaningful proportion of MWBs is wrong.
  • Exit question: False. Input must be sorted; low <= high ensures the one remaining candidate is tested.
