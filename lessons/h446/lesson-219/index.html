NEW LEARNING

What must Dijkstra's code remember?

  • Graph: which nodes connect, and their edge weights.
  • Distances: the lowest total cost found so far to each node.
  • Visited: nodes already processed.
  • Previous: which node came before each node on a route.

An adjacency list, dictionaries and a set are useful choices in C#.

I DO · MODEL

How does the code find the shortest route?

Start at A. Finish at D. Every distance is counted from A.

From the graph to C#

STEP 1 · START AT A

Start at A: A = 0. All other distances begin at ∞.

A dictionary keeps these best-known distances.

STEP 2 · ADD THE COSTS

From A, B = 4 and C = 1. Visit C next because 1 is smaller.

Via C, B = 1 + 2 = 3. This beats B's old distance of 4.

STEP 3 · READ THE C#

Calculate the total, then save it only if smaller:

int candidate = distance[current] + weight;
if (candidate < distance[neighbour])
{
    distance[neighbour] = candidate;
    previous[neighbour] = current;
}

Save C as B's previous node to trace the route back.

STEP 4 · MAKE IT EFFICIENT

Scanning every node each time: O(V²).

With an adjacency list and a binary-heap priority queue: O((V + E) log V).

V = vertices (nodes) · E = edges (connections)

PART 2 · OCR-STYLE CODE QUESTION · 6 MARKS

A program uses the following code while finding a shortest route. Explain the purpose of the calculation, the IF statement and the previous-node assignment. [6]

int candidate = distance[current] + weight;
if (candidate < distance[neighbour])
{
    distance[neighbour] = candidate;
    previous[neighbour] = current;
}
MARK SCHEME

[6] Takes the total distance to current [1] and adds the edge's weight to find the candidate route cost [1]. Compares it with the existing best-known distance [1] and only changes the value if the route is shorter [1]. Updates the neighbour's distance [1] and stores current as the previous node so the route can be reconstructed [1].

PART 3 · OCR-STYLE EFFICIENCY QUESTION · 4 MARKS

Explain why using a priority queue may be more suitable than repeatedly scanning every node when applying Dijkstra to a large, sparse network. [4]

MARK SCHEME

[4] A full scan repeatedly examines many nodes to find the next smallest distance [1]. A priority queue prioritises the nodes by distance [1]. This can reduce the work needed to choose the next node [1], making the approach more efficient for large, sparse graphs [1].
