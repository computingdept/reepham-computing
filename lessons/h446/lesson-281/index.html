Data capture, integrity and ACID transactions

By the end you can…
  • Data capture gathers data, while validation, verification and referential integrity address different correctness concerns.
  • Atomicity ensures a transaction is all-or-nothing; consistency preserves constraints; isolation addresses concurrent interference; durability keeps committed results.
  • Row locking, transactions and appropriate constraints help prevent two concurrent changes from corrupting financial or stock records.

BEGIN TRANSACTION;

UPDATE Account SET Balance=70 WHERE ID='B';
COMMIT;
-- If either fails, ROLLBACK instead.
-- Total A+B must remain 150.

I DO · MODEL

A stock purchase needs to reduce Stock and create Order together. Why use a transaction?

BEGIN; decrement stock; create Order; COMMIT.
On failure → ROLLBACK.
STEP 1 OF 2

Predict

Both writes must succeed together or be undone so stock does not change without a valid order.
