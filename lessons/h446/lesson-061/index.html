Lesson 061 · Thinking Ahead: Inputs, Preconditions and Reuse

By the end you can…
  • Specify the inputs and outputs before choosing algorithms: ticket count and unit price determine total charge.
  • Make preconditions explicit. Invalid negatives or overflow can produce incorrect outputs; validation and appropriate types reduce risks.
  • Caching saves a previously computed result for reuse, trading memory and stale-result risk against repeated calculation time. Reusable methods reduce repeated code.

static int Cost(int tickets,int price){
 if(tickets<0 || price<0)
  throw new ArgumentOutOfRangeException();
 return tickets*price;
}
// input: 3 tickets, £4 each → £12
// precondition: both are non-negative.
