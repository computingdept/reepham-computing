NEW LEARNING · EXAMPLE FIRST

Study the worked scenario

// Reservation system
// Unit: test ValidDate(date) alone.
// Integration: test booking + database write.
// System: test the complete reservation flow.
// Acceptance: confirm it meets the client's needs.
STEP 1 OF 3

Test individual units

Unit tests isolate one function or class method from the rest of the system.

STEP 2 OF 3

Test connections and behaviour

Integration tests interactions between modules; system tests the complete application.

STEP 3 OF 3

Confirm intended outcome

Acceptance testing checks whether the delivered application meets stakeholder requirements. Automated regression tests rerun after changes.

I DO · TEACHER MODEL

A checkout computes the right total but fails to save orders. Which test is most relevant?

TotalCalculator → OrderService → Database
Correct total; saving fails.
STEP 1 OF 2

Predict first

TotalCalculator already gives correct values; the failure appears when OrderService interacts with the database.

STEP 2 OF 2

Model and explain

Prioritise an integration test of saving, then a system-level end-to-end checkout test.

WE DO · DIFFERENT GUIDED PROBLEM

A search function works alone but the website shows the wrong results. What should be tested?

Search() returns expected IDs.
Website displays mismatched titles.
STEP 1 OF 2

Predict first

The isolated search passes, so check the connection that maps returned IDs to displayed titles.

STEP 2 OF 2

Model and explain

An integration test can expose the mapping mismatch, while a system test checks the complete user-visible result.

Core · 6 marks · QUESTION 2 OF 3

A login test passes until a new password rule is introduced, after which registration fails. Explain a sensible debugging and testing workflow.

WORKED ANSWER

[6] Reproduce failure [1]; inspect changed rule and expected behaviour [1]; step through registration [1]; correct fault [1]; rerun registration unit/integration tests [1]; rerun previous login tests for regression [1].

Stretch · 6 marks · QUESTION 3 OF 3

Why is 100% execution of code lines not equivalent to proving an application correct? Suggest three further forms of evidence.

WORKED ANSWER

[6] Executing every line may not test all branches or input combinations [2]; use boundary and erroneous test cases [1], integration tests [1], realistic user acceptance scenarios [1] and regression tests after changes [1].
