CODE / ALGORITHM FIRST

Work through the algorithm

static void QuickSort(int[] a,int low,int high) {
  if (low >= high) return; // 0 or 1 element
  int p = Partition(a,low,high);
  QuickSort(a,low,p-1);
  QuickSort(a,p+1,high);
}
// Partition uses the last-element pivot
// and returns the pivot's final index.
STEP 1 OF 3

Stop small subarrays

When low>=high there are zero or one elements to sort: return immediately.

STEP 2 OF 3

Partition then divide

Partition places the pivot at its final index p. Do not recursively include index p.

STEP 3 OF 3

Sort two sides independently

Call QuickSort on low..p−1 and p+1..high. The pivot itself stays fixed.

Describe the average and worst-case time complexity of quicksort, why these can differ, and one implementation trade-off relative to merge sort.

MODEL ANSWER

[6] Average O(n log n) [1] with balanced partitions [1]; worst O(n²) [1] with repeated unbalanced partitions [1]; in-place partitioning typically uses less additional array space than merge sort [1], though recursive quicksort still uses call-stack space [1].
