NEW LEARNING · CODE FIRST

Read the code; predict its effect

// For a given positive n:
int linearSteps = 0;
for (int i = 0; i < n; i++) linearSteps++;

int nestedSteps = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) nestedSteps++;
// For n=4: linearSteps=4; nestedSteps=16.
STEP 1 OF 3

Count what grows

Big O describes how work increases with input size, not the exact milliseconds on one computer.

STEP 2 OF 3

Compare search

Linear search can take n checks; binary search on sorted input roughly halves the remaining candidates each step.

STEP 3 OF 3

Compare sorting

A simple nested comparison loop can be O(n²), whereas merge sort is O(n log n).

Foundation · 1 OF 3

Name the complexity of a single loop visiting n values.

WORKED ANSWER

O(n).

Core · 2 OF 3

An array has 128 ordered items. Compare linear and binary worst-case checks.

WORKED ANSWER

Linear up to 128 checks; binary up to 8 checks with a standard midpoint search.

Stretch · 3 OF 3

Is binary search always better than linear search? Give one counterexample.

WORKED ANSWER

No. An unsorted tiny array can be searched linearly without sorting. Binary search first needs sorted data, and sorting/preparation may cost more than one scan.

TERM 1 OF 5

time complexity

How an algorithm's work grows with input size.

TERM 2 OF 5

O(n)

Work proportional to input count.

TERM 3 OF 5

O(log n)

Work proportional to the number of halvings.

TERM 4 OF 5

O(n²)

Quadratic growth, often nested loops.

TERM 5 OF 5

trade-off

A benefit balanced against another cost.

True or false?

O(log n) means execution time is literally log n seconds.

MODEL ANSWER

False. It describes the growth of operations, not a time in seconds.
