Imperative/procedural

STEP 2 OF 3

Declarative

Describe a desired result or logical relationship rather than an explicit control-flow recipe.

STEP 3 OF 3

Object-oriented

Objects group state and behaviour. Inheritance lets a derived class reuse a base class; an override replaces a virtual method. Calling that method through a base-class reference runs the actual object’s version: polymorphism.

I DO · TEACHER MODEL

Compare a SQL query selecting all orders over £100 with a loop that scans each record.

WORKED REASONING

Model answer

SQL describes the required set of matching records (declarative); the loop specifies iteration, testing and append operations (imperative/procedural). Both can produce equivalent output through different expression styles.

I DO · SECOND MODEL · OCR 1.2.4(e)

One method call, different actual object types

using System;
Alert[] alerts = { new EmailAlert(), new PopupAlert() };
foreach (Alert a in alerts)
    Console.WriteLine(a.Show());

class Alert {
    public virtual string Show() => "Generic";
}
class EmailAlert : Alert {
    public override string Show() => "Email";
}
class PopupAlert : Alert {
    public override string Show() => "Popup";
}
STEP 1 · INHERITANCE

Find the parent and children

Alert is the base class; EmailAlert : Alert and PopupAlert : Alert are derived classes. Each is a kind of Alert and can be stored in an Alert[].

STEP 2 · OVERRIDING

Same signature, specialised behaviour

Show() is virtual in Alert. Both derived classes use override to supply their own implementation.

STEP 3 · POLYMORPHISM

Trace the output

a.Show() prints Email then Popup. Although a is declared as Alert, the runtime selects the implementation belonging to the actual object. This is polymorphism, not two separate if tests.

WE DO · SECOND EXAMPLE

Which Speak() method runs?

using System;
Animal[] pets = { new Cat(), new Dog() };
foreach (Animal pet in pets)
    Console.WriteLine(pet.Speak());

class Animal {
    public virtual string Speak() => "...";
}
class Dog : Animal {
    public override string Speak() => "Woof";
}
class Cat : Animal {
    public override string Speak() => "Miaow";
}
STEP 1 · IDENTIFY

Predict the output first

Name the base class and two derived classes. In which order are the actual objects stored in the array?

STEP 2 · TRACE

Apply dynamic dispatch

The first object is a Cat, so its overridden Speak() runs. The second is a Dog. No type-checking if statement is needed.

STEP 3 · CHECK

Explain the actual result

Outputs Miaow then Woof. Animal is the declared reference type; each object’s runtime type determines the overridden method.

CHALLENGE · QUESTION 3 OF 3

A base class Alert declares virtual Show(). Two derived classes EmailAlert and PopupAlert override Show(). An Alert[] contains one of each. Explain inheritance, overriding, polymorphism and one reason this design may be preferable to procedural type-checking. [8]

MARK SCHEME / WORKED ANSWER

Inheritance reuses/specialises Alert [2]; overriding supplies each derived class’s Show implementation [2]; a call through Alert uses the object’s actual type at runtime [2]; shared base contract supports extension without scattered type-checking branches [2].
