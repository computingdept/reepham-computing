Lesson 074 · Big O: Constant, Linear and Logarithmic

By the end you can…
  • Big O describes the upper bound on how work grows with input size, not the precise milliseconds of an execution.
  • A fixed direct index operation is O(1), scanning n values is O(n), and repeatedly halving n is O(log n).
  • For n=64, a linear scan may inspect 64 items, while halving 64→1 takes six halvings. Sorting requirements and constants still matter.

Key vocabulary

I DO · MODEL

Classify loop performing one action for each item in n-element array.

O(n) because it performs n iterations, each O(1) work.
WORKED METHOD

Explain

The number of operations doubles when n doubles.

WE DO · DIFFERENT PROBLEM

Classify a loop n=32; n=n/2 until n<=1.

O(log n); values 32,16,8,4,2,1: five halvings.
WORKED METHOD

Explain

Each iteration cuts remaining size in half.

FOUNDATION · Q1/3

Match direct array access, full array scan and repeated halving with Big O. [6]

WORKED ANSWER

O(1) constant [2], O(n) linear [2], O(log n) logarithmic [2].

APPLY · Q2/3

For input size64, compare scan steps64 and repeated halving to1; calculate halvings. [6]

WORKED ANSWER

64→32→16→8→4→2→1 [4], six halvings [2].

CHALLENGE · Q3/3

Explain why O(log n) binary search may be unsuitable for unsorted data even if asymptotically faster than linear search. [6]

WORKED ANSWER

Binary requires sorted data [2]; preprocessing sort costs time [2]; single lookup may favour linear scan [1], repeated searches justify sorting [1].
