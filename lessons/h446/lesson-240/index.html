NEW LEARNING · CODE FIRST

Follow the example

// Intended ages 12–18 INCLUSIVE
static bool Eligible(int age)
  => age > 12 && age < 18; // BUG
// FIX: age >= 12 && age <= 18
STEP 1 OF 3

Read the stated rule

Because the permitted ages are inclusive, both age 12 and age 18 must be accepted.

STEP 2 OF 3

Locate the Boolean error

The strict comparison operators > and < exclude both valid boundaries.

STEP 3 OF 3

Repair and test

Change to >= and <=; retest the boundaries plus values just outside the range.

I DO · TEACHER MODEL

A score validator intended for 0–10 uses score>0 && score<10. Fix it.

return score>=0 && score<=10;
STEP 1 OF 2

Predict first

The valid endpoints were incorrectly rejected.

STEP 2 OF 2

Model and check

Change the operators to >= and <=, and test −1 and 11 as invalid values.

WE DO · DIFFERENT PROBLEM

A duration validator for 1–60 accepts 61 because it uses OR. Correct it.

return seconds >= 1 && seconds <= 60;
STEP 1 OF 2

Predict first

OR accepts 61 because only one side needs to be true.

STEP 2 OF 2

Model and check

AND requires both limits to hold and correctly rejects 61.

EXAM QUESTION 1 OF 4 · 4 MARKS · 4 MINUTES

Name ONE useful IDE feature for WRITING code and ONE different feature for TESTING or DEBUGGING. Explain precisely what each helps the programmer do. [4]

OCR H446/02 · June 2022 · Q1(d) · RHS exam-style scenario

MODEL ANSWER · 4 MARKS

Writing: autocomplete suggests or finishes identifiers; auto-indent maintains nesting; syntax highlighting distinguishes syntax. Debugging: breakpoint pauses at a line; watch shows variable values; step-through traces execution. Each name must be connected to a relevant use.

Marking: Two feature-and-purpose pairs, with one mark for the writing feature and use, and one for the test/debug feature and use (four marks total).
