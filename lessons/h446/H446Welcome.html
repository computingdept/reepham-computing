Recall

What is the value of the leftmost bit in an 8-bit unsigned number?

ANSWER · EXPLAIN

128. The unsigned place values are 128, 64, 32, 16, 8, 4, 2, 1.

QUESTION 3 OF 4 · GCSE FOUNDATIONS

Recall

If a computer stores negative numbers, why must we agree a representation?

ANSWER · EXPLAIN

The same bit pattern can mean different values under different signed-binary conventions.

QUESTION 4 OF 4 · GCSE FOUNDATIONS

Recall

Why can an unsigned byte store 255 but not 256?

ANSWER · EXPLAIN

Eight bits give 256 patterns, including zero: 0–255. Representing 256 needs nine bits.

THE BIG IDEA · 8 BITS

Bits need a rule

Before interpreting a bit pattern, decide:

  1. How many bits?
  2. Unsigned, sign and magnitude, or two's complement?
  3. Where is the binary point, if any?
8-bit sign and magnitude
1 sign + 7 magnitude bits
8-bit two's complement
Leftmost bit has weight −128
Signed 4.4 fixed point
Integer weights −8, 4, 2, 1; fraction weights ½, ¼, ⅛, ¹⁄₁₆
STEP 1 OF 4

Sign and magnitude · −13

Reserve one bit for sign (0 = positive, 1 = negative). Convert 13 to seven-bit binary, then put 1 in front.

10001101

1 | 0001101 = −13. 8-bit range: −127 to +127, with two patterns for zero.

1 of 4
STEP 2 OF 4

Two's complement · −13

Start with positive 13 as 00001101. Invert every bit, then add 1.

+13      00001101
Invert   11110010
Add 1    11110011

One zero; 8-bit range: −128 to +127. For this pattern: −128 + 64 + 32 + 16 + 2 + 1 = −13.

2 of 4
STEP 3 OF 4

Fixed point · 5.25

Agree where the binary point goes. For this example, four bits are to its left and four to its right.

0101.0100

4 + 1 + ¼ = 5.25. Fraction weights: ½, ¼, ⅛, ¹⁄₁₆.

Signed 4.4 two's complement also works: 1101.1000 = −2.5 (−8 + 4 + 2 + ½).

3 of 4
STEP 4 OF 4

Know the boundary

These representations are not interchangeable. A bit pattern needs its width, signed convention and, for fractions, binary-point position.

Same bits, different meanings:
10001101 = 141 unsigned; −13 in sign and magnitude; −115 in two's complement.

Fixed point is a bridge to floating-point representation later in OCR H446 1.4.1(g).

YOU DO · CODE FIRST · C#

Build an 8-bit signed decoder

A user types a number from 0 to 255 representing eight bits. Write a C# console program that outputs its value when interpreted as 8-bit two's complement.

Rule: if the raw value is 128 or more, subtract 256; otherwise leave it unchanged.

Console.Write("Enter 0–255: ");
int raw = int.Parse(Console.ReadLine()!);

int signedValue = raw; // TODO: replace with the signed 8-bit value
// Hint: values 128–255 represent negative numbers

Console.WriteLine("Signed value: " + signedValue);

Test: 13 → 13 · 243 → −13 · 250 → −6 · 128 → −128

Stretch: check for an out-of-range input; divide the signed value by 16.0 to decode signed 4.4 fixed point.

MODEL SOLUTION · REVIEW AFTER CODING
Console.Write("Enter 0–255: ");
int raw = int.Parse(Console.ReadLine()!);

if (raw < 0 || raw > 255)
{
    Console.WriteLine("Enter a number from 0 to 255.");
}
else
{
    int signedValue = raw >= 128 ? raw - 256 : raw;
    Console.WriteLine("Signed value: " + signedValue);
    double fixedPoint = signedValue / 16.0;
    Console.WriteLine("Signed 4.4 value: " + fixedPoint);
}

Run the listed tests. For 216, the signed value is −40 and the signed 4.4 value is −2.5.
