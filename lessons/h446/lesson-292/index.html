CSS and JavaScript

By the end you can…
  • CSS controls presentation using selectors and declarations; `#status` targets one element by id.
  • JavaScript can react to browser events and modify the DOM. The handler does not execute until a click event occurs.
  • The document's structure remains HTML, styles remain CSS, and interactive behaviour is JavaScript. Validate incoming data on the server even if scripts check it first.

NEW LEARNING · WORKED EXAMPLE FIRST

Trace the mechanism

<p id='status'>Waiting</p>
<button id='go'>Start</button>
<style>
 #status { color: blue; font-weight: bold; }
</style>
<script>
 document.getElementById('go').addEventListener('click',()=>{
   document.getElementById('status').textContent='Ready';
 });
</script>

I DO · MODEL

Trace click count initial 0 when handler increments by one on each click. Two clicks occur.

let count=0;
button.onclick=()=>{count=count+1;};
// after two clicks, count=2
STEP 1 OF 2

Predict first

Start with count=0; first click handler adds one making count=1.

STEP 2 OF 2

Show method

Second click adds one again giving count=2; no change happens before an event.

WE DO · DIFFERENT QUESTION

A page contains p id='msg' showing 'Off'. Click handler changes textContent to 'On'. Explain DOM result.

document.getElementById('msg').textContent='On';
STEP 1 OF 2

Predict first

getElementById selects the existing paragraph whose id is 'msg'.

STEP 2 OF 2

Show method

Assigning textContent replaces displayed text with 'On'; it is safer for text than injecting untrusted HTML.
