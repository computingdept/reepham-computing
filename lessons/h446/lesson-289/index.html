Hashing and applications

By the end you can…
  • A cryptographic hash transforms an arbitrary input into a fixed-size digest. It is designed to make reversing the digest infeasible, not impossible under all circumstances.
  • A message digest supports integrity checking when the reference hash is trusted. Hash collisions can exist because outputs have finite length.
  • Passwords should be processed using a salted, purpose-built slow password-hashing scheme, not simply a fast general-purpose hash and never reversible encryption.

I DO · MODEL

A downloaded file's trusted SHA-256 checksum differs from the computed checksum. What can you conclude?

expected = digest_A
actual   = digest_B
expected != actual
STEP 1 OF 2

Predict first

The file contents or expected reference differ: the integrity check fails.

STEP 2 OF 2

Show method

The mismatch does not by itself reveal whether alteration was accidental or malicious.

WE DO · DIFFERENT QUESTION

Two users choose the same password. How can salts improve their stored password verifiers?

verifierA = KDF(saltA, password)
verifierB = KDF(saltB, password)
STEP 1 OF 2

Predict first

Different random salts make identical passwords produce different stored verifiers.

STEP 2 OF 2

Show method

A costly password KDF slows guessing; salt is generally stored beside the verifier and need not be secret.

FOUNDATION · Q1 OF 3

Define cryptographic hashing and distinguish it from reversible encryption. [6]

MODEL ANSWER

Hash maps data to fixed-length digest [2], designed one-way [1]; encryption designed to recover plaintext with key [2]; hashes are not decrypted [1].

CORE · Q2 OF 3

Explain how a trusted checksum helps verify a software download and give one limitation. [6]

MODEL ANSWER

Compute digest of downloaded bytes [2]; compare with trusted expected digest [2]; match is strong integrity evidence [1]; compromised reference cannot establish authenticity [1].

CHALLENGE · Q3 OF 3

Explain salted password hashing and why storing raw passwords or just fast unsalted hashes is weaker. [6]

MODEL ANSWER

Unique random salt per account [2], purpose-built slow KDF [2], prevents direct same-password verifier equality/precomputed attacks [1], raw or weak unsalted hashes expose credentials [1].
