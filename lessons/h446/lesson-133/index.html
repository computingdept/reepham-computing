I DO · MODELLED

A publisher provides a trusted SHA-256 digest of a file. Explain how a pupil can check the download.

STEP 1 OF 3

Trusted published digest

Find the given data and name the required result.

STEP 2 OF 3

Calculate downloaded hash

Explain why this intermediate stage is necessary.

STEP 3 OF 3

Compare exact digests

Calculate SHA-256 digest of received file and compare with the digest from a trusted source. If different, file changed or was corrupted. If equal, this strongly supports matching content, assuming trusted digest and secure algorithm; it does not by itself prove publisher identity.

WE DO · DIFFERENT CASE

A database stores plaintext passwords. Explain a better use of hashing.

STEP 1 OF 3

Choose random salt

Find the given data and name the required result.

STEP 2 OF 3

Derive slow password hash

Explain why this intermediate stage is necessary.

STEP 3 OF 3

Store salt plus result

Store unique salts and outputs from a slow password-hashing scheme such as Argon2id, not reversible encryption or a plain fast hash. On login, recompute using stored salt and compare securely.

FOUNDATION · QUESTION 1 OF 3

State three different uses of hashing with one correct explanation each. [6]

MARK SCHEME / WORKED ANSWER

APPLICATION · QUESTION 2 OF 3

Explain what a hash collision is and why it matters. [6]

MARK SCHEME / WORKED ANSWER

Distinct inputs can share a hash [2], finite output range implies possible collisions [2], robust use selects collision-resistant function/handles table collisions [2].

CHALLENGE · QUESTION 3 OF 3

Evaluate the claim 'a hash can decrypt a password and proves a file came from its claimed author'. [8]

MARK SCHEME / WORKED ANSWER

Hashing is one way not decryption [2], passwords use salting and suitable password KDF [2], digest comparison aids integrity [2], origin needs trusted channel/signature [2].
