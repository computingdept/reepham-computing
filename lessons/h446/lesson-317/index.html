COUNT DISTINCT IN SORTED ARRAY
static int UniqueCount(int[] a){
 if(a.Length==0)return 0;
 int count=1;
 for(int i=1;i<a.Length;i++)
  if(a[i]!=a[i-1])count++;
 return count;
}

CLASS CHECK

Before we move on

Why does a sorted array allow distinct values to be counted by comparing neighbours?

MODEL ANSWER

All occurrences of a value are adjacent, so each new group represents a new distinct value.

EXAM QUESTION 1 OF 4 · 9 MARKS · 9 MINUTES

A developer wants to maintain several ticket-request queues for different auditoriums. Discuss the strengths and weaknesses of an OOP queue CLASS compared with writing procedural queue routines and sharing global arrays. Consider encapsulation, multiple independent instances, maintenance, reuse, testing and complexity. Conclude which approach is appropriate for the theatre. [9]

OCR H446/02 · June 2022 · Q8(c)(ii)* · RHS exam-style scenario

MODEL ANSWER · 9 MARKS

OOP can package each queue's array and pointers privately with public enqueue/dequeue methods, allowing many independent objects, reuse, protection of invariants and easier testing. Procedural modules can also reuse algorithms simply and may have lower conceptual overhead, but shared globals can cause accidental interference between auditoriums. Prefer instances if many queues need independent state, while noting extra class-design effort.

Marking: Teacher-assessed nine-mark holistic bands: high 7–9 balanced application and justified evaluation; middle 4–6 sound; low 1–3 basic; zero none. Human moderation required.

EXAM QUESTION 2 OF 4 · 9 MARKS · 9 MINUTES

The students creating Undersea Trail are debating whether variables such as current position, prize data, money and player status should be global or local. Discuss benefits and risks of global variables compared with local variables and passing values into routines. Apply your discussion to the game's modules and explain which design choices you would recommend for long-term maintenance. [9]

OCR H446/02 · June 2024 · Q9(f)* · RHS exam-style scenario

MODEL ANSWER · 9 MARKS

Globals allow different routines to access shared game state easily but increase coupling, create unintended changes, make tests dependent on call order and complicate debugging. Locals and method parameters improve encapsulation, reuse and testing, but require passing or returning data, and not every value can remain isolated. Shared state can be held within an Explorer object or a dedicated game controller and exposed through clear methods. Recommend limiting globals and designing explicit interfaces while acknowledging sensible shared configuration values.

Marking: Holistic nine-mark teacher marking: detailed/balanced applied design and substantiated recommendation 7–9; sound partial evaluation 4–6; basic relevant statements 1–3; 0 no credit. Not a fixed keyword checklist.

RHS ADDITIONAL PRACTICE · QUESTION 3 OF 4 · 2 MARKS · 2 MINUTES

A student says that encapsulation makes a queue class safer. Explain how private attributes and public enqueue and dequeue methods support this claim. [2]

RHS original follow-on question · optional extension after timed extended responses

MODEL ANSWER · 2 MARKS

Private attributes prevent outside code from directly changing the queue's internal state. Public methods control updates and can enforce rules such as checking whether the queue is full or empty.

Marking: One mark for restricting direct access; one for controlled updates or enforcement of queue rules.

RHS ADDITIONAL PRACTICE · QUESTION 4 OF 4 · 2 MARKS · 2 MINUTES

A game contains a global variable named score that several unrelated functions modify. Explain why passing the score explicitly as a parameter and returning an updated value can make testing easier. [2]

RHS original follow-on question · optional extension after timed extended responses

MODEL ANSWER · 2 MARKS

A function can be tested with a known input and its returned result checked independently. The test is less dependent on hidden shared state or the order in which other functions have executed.

Marking: One mark for supplying known input and checking the returned output; one for reducing dependence on shared state or call order.
