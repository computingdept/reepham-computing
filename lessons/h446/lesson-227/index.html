NEW LEARNING · CODE FIRST

Study the code and predict the state

// C# top-level statements must precede type declarations.
Counter c = new();
c.Add(4); // Set a breakpoint after this call.
Console.WriteLine(c.Count); // 4

class Counter {
  public int Count { get; private set; }
  public void Add(int n) { Count += n; }
}
STEP 1 OF 3

Set a breakpoint

Pause at a method call or the following instruction to inspect current state.

STEP 2 OF 3

Step into to inspect internals

Step Into executes the called method one instruction at a time. Watch Count and parameter n.

STEP 3 OF 3

Step over to skip internals

Step Over runs the entire call and pauses at the next statement, allowing you to inspect the result.

I DO · TEACHER MODEL

A Score class has Points=3. Add(5) should change Points to 8. Identify a wrong line.

void Add(int amount) {
  int points = Points + amount; // wrong
}
STEP 1 OF 3

Predict first

Step Into Add and inspect the local points and the field Points.

STEP 2 OF 3

Model the reasoning

The local becomes 8 while the object field remains 3; the assignment targets the wrong variable.

STEP 3 OF 3

Model the reasoning

Replace it with Points += amount; and rerun. The field should be 8.

WE DO · DIFFERENT GUIDED PROBLEM

A Lamp starts IsOn=false. Toggle() sets IsOn=true on every call. Diagnose the second-call error.

void Toggle() {
  IsOn = true; // wrong
}
STEP 1 OF 2

Predict first

After the first call, true is correct; after the second, IsOn should become false.

STEP 2 OF 2

Model the reasoning

The method always assigns true, so the second call fails. Fix to IsOn = !IsOn; and test twice.

EXAM QUESTION 1 OF 4 · 4 MARKS · 4 MINUTES

Name ONE useful IDE feature for WRITING code and ONE different feature for TESTING or DEBUGGING. Explain precisely what each helps the programmer do. [4]

OCR H446/02 · June 2022 · Q1(d) · RHS exam-style scenario

MODEL ANSWER · 4 MARKS

Writing: autocomplete suggests or finishes identifiers; auto-indent maintains nesting; syntax highlighting distinguishes syntax. Debugging: breakpoint pauses at a line; watch shows variable values; step-through traces execution. Each name must be connected to a relevant use.

Marking: Two feature-and-purpose pairs, with one mark for the writing feature and use, and one for the test/debug feature and use (four marks total).

EXAM QUESTION 2 OF 4 · 6 MARKS · 6 MINUTES

A programmer is diagnosing errors in a ticket-booking application. Name THREE distinct debugging features available in an IDE. For each, explain exactly how it could help identify the cause of a fault. [6]

OCR H446/02 · June 2023 · Q7(d) · RHS exam-style scenario

MODEL ANSWER · 6 MARKS

Breakpoints pause execution at selected statements; stepping follows one statement/call at a time; a watch window displays variable changes; error diagnostics identify syntax/runtime errors; syntax highlighting makes structural errors easier to see. Any suitable three are allowed.

Marking: Three feature-plus-use pairs at two marks each, maximum six. Name alone earns only the identification mark.

RHS ADDITIONAL PRACTICE · QUESTION 3 OF 4 · 2 MARKS · 2 MINUTES

A ticket-booking program calculates the wrong total but does not crash. Explain how a watch window would help locate the error. [2]

RHS original follow-on question · linked to this lesson's exam practice

MODEL ANSWER · 2 MARKS

Add relevant variables such as price, quantity and total to the watch window; inspect how their values change while the program executes to identify the first incorrect value.

Marking: 1 mark for watching relevant variables; 1 mark for comparing their changing values to the expected calculation.

RHS ADDITIONAL PRACTICE · QUESTION 4 OF 4 · 2 MARKS · 2 MINUTES

A fault occurs inside a method called calculateTotal(). Explain why stepping INTO the method is more useful than stepping OVER it when investigating that fault. [2]

RHS original follow-on question · linked to this lesson's exam practice

MODEL ANSWER · 2 MARKS

Step into enters calculateTotal() and lets the programmer inspect its individual statements and values. Step over executes the method call without showing the statements inside it.

Marking: 1 mark for stepping into the called method; 1 mark for the contrast with stepping over.

True or false?

Step Over a method call means it is not executed.

Model answer

False. The call executes; the debugger does not stop inside it.
