Lesson 091 · Fetch–Decode–Execute: A Register Trace

By the end you can…
  • Fetch copies the address from PC to MAR; memory read transfers the instruction through MDR into CIR. In a sequential fetch, PC advances.
  • The Control Unit decodes the current instruction held in CIR and produces the necessary control signals.
  • Execution of LDA 80 reads the data held at memory address 80 into ACC; the next instruction is not executed until its own fetch.

Key vocabulary

fetchdecodeexecuteCIRACC
NEW LEARNING · PROCESSOR CITY AND HARDWARE

Trace the hardware

// Illustrative accumulator machine, not exact ISA
PC=20; memory[20]=LDA 80; memory[80]=13
FETCH: MAR←PC (20); MDR←memory[20]
       CIR←MDR; PC←PC+1 (21)
DECODE: CU recognises LDA 80
EXECUTE: MAR←80; MDR←memory[80] (13)
         ACC←MDR (13)

I DO · WORKED MODEL

PC=30, memory[30]=ADD 70, memory[70]=5, ACC=4. Trace after fetch and execute.

MODEL EXPLANATION

Explain the mechanism

Fetch: MAR30, CIR ADD70, PC31. Execution reads memory[70]=5 and ALU adds to ACC4, giving ACC9.

The PC increments in fetch while the ALU operates on ACC and fetched operand.

WE DO · DIFFERENT QUESTION

PC=42, memory[42]=SUB 90, memory[90]=3, ACC=11. Trace registers and result.

MODEL EXPLANATION

Explain the mechanism

After fetch PC43,CIR SUB90. Operand read from90 into MDR=3; ALU computes11−3, ACC8.

The addressed operand must not be confused with instruction address42.
