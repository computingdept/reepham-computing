Key vocabulary

termination

Reaching a condition where the algorithm stops.

recursive step

Calling the function on a smaller or simpler input.

iteration

Repeating instructions using a loop.

stack overflow

Failure when active calls exhaust available stack space.

precondition

An input rule assumed by an algorithm.

NEW LEARNING · CODE FIRST

What is the program actually doing?

int CountDigits(int n)
{
    if (n < 10) return 1;
    return 1 + CountDigits(n / 10);
}

Assume n is positive. Integer division by 10 removes the final digit at each call.

STEP 1 OF 3

Find the smallest problem

A positive single-digit number needs one digit. So n &lt; 10 is our base case.

STEP 2 OF 3

Make progress

For n ≥ 10, integer division by 10 makes the number shorter: 4827 → 482 → 48 → 4.

STEP 3 OF 3

Count on the way back

4 returns 1. Then 48 returns 2; 482 returns 3; 4827 returns 4.

Recursion versus iteration

int CountDigitsLoop(int n)
{
    int count = 1;
    while (n >= 10)
    {
        n /= 10;
        count++;
    }
    return count;
}

Both work for non-negative integers. A recursive function uses self-calls and stack frames. A loop repeats within one call and can reuse variables. Recursion can be clearer for tree-shaped problems; iteration often uses less stack memory.

EXAM QUESTION 2 OF 3 · 3 MARKS · 3 MINUTES

Write a recursive function in C# that returns 2 to the power n, for a non-negative integer n. [3]

MODEL ANSWER · 3 MARKS
int PowerTwo(int n) {
    if (n == 0) return 1; // base case [1]
    return 2 * PowerTwo(n - 1); // recursive call [1], correct multiplication [1]
}
EXAM QUESTION 3 OF 3 · 3 MARKS · 3 MINUTES

Compare recursion with iteration. Give two differences and one advantage of recursion for a suitable problem. [3]

MODEL ANSWER · 3 MARKS

Recursion repeats through self-calls; iteration repeats using a loop [1]. Recursive calls normally need separate stack frames, whereas a simple loop can reuse variables [1]. Recursion can express naturally recursive problems such as tree traversal more clearly [1].
