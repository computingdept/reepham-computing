NEW LEARNING · CODE FIRST

Study the code and predict the state

// C# top-level statements come before class declarations.
var a = new Account(20);
a.Deposit(5);
Console.WriteLine(a.Balance); // 25

class Account {
  public int Balance { get; private set; }
  public Account(int balance) { Balance = balance; }
  public void Deposit(int amount) {
    if (amount > 0) Balance += amount;
  }
}
STEP 1 OF 3

Inspect class state

The object has a Balance property initially set by its constructor.

STEP 2 OF 3

Trace method inputs

Deposit(5) passes amount=5. Since amount>0, Balance+=5 executes.

STEP 3 OF 3

Debug the outcome

Expected Balance=25. If unchanged, check whether the code assigns to Balance or merely calculates a temporary value.

I DO · TEACHER MODEL

Find and correct the fault when AddPoints(3) fails to update Score=7.

public void AddPoints(int points) {
  int newScore = Score + points;
  // BUG: Score never assigned
}
STEP 1 OF 3

Predict first

The local newScore becomes 10, but the field Score remains 7.

STEP 2 OF 3

Model the reasoning

Replace the local-only calculation with Score += points;.

STEP 3 OF 3

Model the reasoning

Retest: after AddPoints(3), Score should equal 10.

WE DO · DIFFERENT GUIDED PROBLEM

A Counter starts at 2. Increment() contains `Count + 1;`. Explain the problem and fix it.

public void Increment() {
  Count + 1; // invalid statement in C#
}
STEP 1 OF 2

Predict first

Count + 1 does not assign a new value and is not a valid standalone statement in C#.

STEP 2 OF 2

Model the reasoning

Correct it to Count++; or Count += 1;. With Count=2, the resulting Count is 3.

Foundation · 4 marks · QUESTION 1 OF 3

An object starts at Count=4 and runs Increment() which performs Count += 1. What is Count after three calls?

WORKED ANSWER

[4] 5 after first [1], 6 after second [1], 7 after third [1]; each call updates the same object's field [1].

Core · 6 marks · QUESTION 2 OF 3

Correct `public void SetAge(int age) { int Age = age; }` where Age is an existing property. Explain why it fails.

WORKED ANSWER

[6] `int Age` declares a new local variable [2], shadowing rather than updating the member [1]; use `this.Age = age;` [2]; test SetAge(16) sets property to 16 [1].

Stretch · 6 marks · QUESTION 3 OF 3

A BankAccount.Withdraw(amount) rejects only amounts <=0, but permits overdrafts. Add validation and give boundary tests for Balance=50.

WORKED ANSWER

[6] Reject amount<=0 [1] and amount>Balance [1]; valid update Balance-=amount [1]. Boundary tests: Withdraw(50) gives 0 [1], Withdraw(51) is rejected [1], Withdraw(0) is rejected [1].
