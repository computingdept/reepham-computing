Lesson 057 · C# Data Structures Mini-project: Library Loans

By the end you can…
  • Class Loan models a single loan request, containing a student and book title initialised in its constructor.
  • Queue<Loan> stores objects in requested service order. Enqueue adds a new request and Dequeue retrieves oldest.
  • For a more complete system, use a Dictionary keyed by unique loan ID, validation and tests; do not treat a name as necessarily unique.
  • Introduce OCR file reading/writing so loan records can persist beyond the current in-memory queue.

NEW LEARNING · CODE FIRST

Trace the example

using System;
using System.Collections.Generic;
var loans = new Queue<Loan>();
loans.Enqueue(new Loan("Ada", "Holes"));
loans.Enqueue(new Loan("Ben", "Dune"));
Console.WriteLine(loans.Dequeue().Student); // Ada

class Loan {
 public string Student { get; }
 public string Book { get; }
 public Loan(string student, string book) {
  Student = student; Book = book;
 }
}
STEP 1 OF 3

Understand

Class Loan models a single loan request, containing a student and book title initialised in its constructor.

STEP 2 OF 3

Model

Queue<Loan> stores objects in requested service order. Enqueue adds a new request and Dequeue retrieves oldest.

STEP 3 OF 3

Evaluate

For a more complete system, use a Dictionary keyed by unique loan ID, validation and tests; do not treat a name as necessarily unique. A queue exists only while the program keeps it in memory; a text file can persist loan records. In OCR examination pseudocode, openWrite plus writeLine writes a file (overwriting existing contents), while openRead plus readLine retrieves lines. Always close() the file.

I DO · MODEL

Trace two loan objects in a queue: Ida first, Tom second. Which is processed first?

enqueue Ida, enqueue Tom, then dequeue → Ida.
WORKED EXPLANATION

Explain

Queue is FIFO, so the first enqueued request is processed first.

I DO · INTRODUCE FILE PERSISTENCE

Persist the library's two processed loans

// OCR H446 examination pseudocode
f = openWrite("loans.txt")
f.writeLine("Ada,Holes")
f.writeLine("Ben,Dune")
f.close()
STEP 1 · OPEN FOR WRITING

Why a file?

Unlike the queue, the text file can hold a record across program runs. openWrite creates a write stream and replaces any existing contents of the target file; it is not an append operation.

STEP 2 · WRITE TWO LINES

Trace the file contents

First writeLine stores Ada,Holes, then the second stores Ben,Dune. They become two separate text lines. This is a simple illustrative format, not a robust CSV parser.

STEP 3 · CLOSE THE FILE

Explain the effect

f.close() finishes the write operation and releases the file. Do not confuse storing records in a queue or dictionary with saving them permanently.

WE DO · DIFFERENT PROBLEM

A different library uses Dictionary<int,Loan> keyed by ID, entries 10 and 12. Which ID does lookup 12 retrieve?

loansById[12] returns the Loan stored under ID 12, regardless of insertion order.
WORKED EXPLANATION

Explain

A dictionary retrieves by key; it does not enforce FIFO service order.

WE DO · READ A SAVED FILE

Read loans.txt, containing Ada,Holes and Ben,Dune on separate lines.

// OCR H446 examination pseudocode
f = openRead("loans.txt")
while NOT f.endOfFile()
    print(f.readLine())
endwhile
f.close()
STEP 1 · YOUR TURN

Predict what is printed

Identify the role of endOfFile() and the effect of each readLine() call.

STEP 2 · TRACE THE FILE POSITION

Follow two reads

The first call prints Ada,Holes; the second prints Ben,Dune. The file position advances after each read.

STEP 3 · CHECK TERMINATION

Stop safely

Once no unread lines remain, endOfFile() is true, the loop stops, and f.close() releases the reader. This example reads text; it does not reconstruct Loan objects automatically.
