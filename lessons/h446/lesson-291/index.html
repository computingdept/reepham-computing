HTML structures and forms

By the end you can…
  • HTML uses nested elements to give structure and semantics: head contains metadata and body contains visible content.
  • Forms collect and submit inputs. The label's for value matches input's id; the input's name is the key submitted to the server.
  • With method GET, query parameters appear in the URL; don't use GET for confidential credentials. Client-side required validation improves usability but is not a substitute for server validation.

NEW LEARNING · WORKED EXAMPLE FIRST

Trace the mechanism

<!doctype html>
<html lang="en">
<head><title>Revision</title></head>
<body>
 <h1>Choose a topic</h1>
 <form action="/search" method="get">
  <label for="topic">Topic</label>
  <input id="topic" name="topic" required>
  <button type="submit">Find</button>
 </form>
</body>
</html>

I DO · MODEL

What is sent by a GET form whose input name is q and value is binary?

<form action='/find' method='get'>
 <input name='q' value='binary'>
</form>
→ /find?q=binary
STEP 1 OF 2

Predict first

The action sets the destination path '/find' and GET encodes form fields into URL query parameters.

STEP 2 OF 2

Show method

The input name 'q' becomes the query key and 'binary' the value.

WE DO · DIFFERENT QUESTION

Correct the accessible label connection in a form where for='email' but input id='user'.

<label for='email'>Email</label>
<input id='email' name='email' type='email'>
STEP 1 OF 2

Predict first

The label for and input id must match exactly.

STEP 2 OF 2

Show method

The email input type provides built-in browser constraints, but the server must validate again.
