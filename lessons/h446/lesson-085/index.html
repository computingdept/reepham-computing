Lesson 085 · Searching, Sorting and Pathfinding Comparison

By the end you can…
  • Start from the problem and input: searching, ordering and weighted paths are different problem classes.
  • A fastest method under one set of assumptions may be invalid or less suitable on another dataset; include preprocessing and memory costs.
  • Choose using correctness, worst-case growth, memory, stability where relevant, and an independent trace on new values.

NEW LEARNING · ALGORITHM STATE VISUALISATION

Follow the worked example

TASK → ALGORITHM (WITH PRECONDITION)
Unsorted exact match → Linear Search O(n)
Sorted exact match → Binary Search O(log n)
Small/nearly-sorted → Insertion Sort
Large general array → Merge Sort O(n log n)
Non-negative shortest paths → Dijkstra
Guided shortest path → A* with sound heuristic

I DO · WORKED

Choose algorithm for 200 sorted pupils by ID with repeated lookups.

Binary search O(log n) is valid because identifiers are sorted; if indexed dictionary is available, keyed lookup is another option.

Method and result

Binary search O(log n) is valid because identifiers are sorted; if indexed dictionary is available, keyed lookup is another option.

WE DO · DIFFERENT VALUES

Choose method for shortest road journey across a network with non-negative costs but no heuristic.

Dijkstra finds least-cost path with non-negative edge weights; do not confuse with array search.

Method and result

Dijkstra finds least-cost path with non-negative edge weights; do not confuse with array search.

FOUNDATION · Q1/3

Identify suitable algorithm for (a) unsorted match (b) sorted match (c) non-negative weighted shortest path. [6]

MARK SCHEME / WORKING

Linear [2], binary [2], Dijkstra [2] with correct contexts.

APPLICATION · Q2/3

Compare bubble, insertion, merge and quick sort worst-case time and typical auxiliary memory. [8]

MARK SCHEME / WORKING

Bubble O(n²), O(1) [2]; insertion O(n²),O(1) [2]; merge O(n log n),O(n) [2]; quick O(n²) worst, recursion stack depends on partitions [2].

CHALLENGE · Q3/3

A college searches a million unsorted attendance records once and later queries sorted year-group reports repeatedly. Evaluate algorithms/data processing choices. [6]

MARK SCHEME / WORKING

One-off linear or indexed lookup on original unsorted input [2], sorting/indexing requires preprocessing [1], repeated sorted searches permit binary O(log n) [2], data changes may demand index maintenance [1].
