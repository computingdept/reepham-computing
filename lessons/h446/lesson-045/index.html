NEW LEARNING · CODE FIRST

What is the program actually doing?

int Factorial(int n)
{
    if (n == 0) return 1;   // STOP
    return n * Factorial(n - 1);
}

Assume n is a non-negative integer.

Think: Why does the input get smaller? What stops another call?

STEP 1 OF 3

Start with a small input

Factorial(4) calls Factorial(3); it cannot finish multiplying until the inner call returns.

STEP 2 OF 3

Reach the stopping rule

Factorial(0) returns 1. It makes no further recursive call.

STEP 3 OF 3

Return through the calls

Factorial(1) = 1 × 1; Factorial(2) = 2 × 1; Factorial(3) = 3 × 2; Factorial(4) = 4 × 6 = 24.

I DO · MODEL EXAMPLE

Trace Factorial(3). Show each call and its return value.

int Factorial(int n)
{
    if (n == 0) return 1;
    return n * Factorial(n - 1);
}
STEP 1 OF 3

Calls

3 → 2 → 1 → 0. The argument decreases by one each time.

STEP 2 OF 3

Base case

Factorial(0) returns 1. No more calls occur.

STEP 3 OF 3

Returns

Factorial(1)=1, Factorial(2)=2, Factorial(3)=6. Final answer: 6.

EXAM QUESTION 3 OF 3 · 3 MARKS · 3 MINUTES

Explain why the call stack is needed during recursion. [3]

MODEL ANSWER · 3 MARKS

Stores each active call's parameter/local values [1]; stores the return address or execution state so the caller can resume [1]; the most recent call returns first (LIFO) [1].

True or false?

1. A recursive function calls itself.
2. A base case must make another recursive call.
3. Each active recursive call has its own stack frame.

Model answers

1. True. Recursion involves a function calling itself.
2. False. The base case returns without making another call.
3. True. Each frame stores that call’s own parameters, local values and return information.
