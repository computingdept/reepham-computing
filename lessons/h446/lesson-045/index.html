OCR H446 · 1.4.2

Build an object with a valid initial state

class Account {
 private int balance;
 public Account(int opening) {
  if (opening < 0)
   throw new ArgumentOutOfRangeException();
  balance = opening;
 }
 public int GetBalance() => balance;
}
THINK

Protect the object invariant

The constructor refuses a negative opening balance before storing it. The field is private, so outside code must use approved public methods instead of bypassing validation.

Connect to prior knowledge
MODELLED EXAMPLE

Construct a valid account; control updates

using System;

Account savings = new Account(10);
savings.Deposit(5);
Console.WriteLine(savings.GetBalance());

class Account {
    private int balance;
    public Account(int opening) {
        if (opening < 0)
            throw new ArgumentOutOfRangeException();
        balance = opening;
    }
    public int GetBalance() => balance;
    public void Deposit(int amount) {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException();
        balance += amount;
    }
}
One complete worked example
STEP 1

Constructor sets the initial state

new Account(10) invokes Account(int opening). It checks 10 is non-negative, then stores 10 in the private field balance.

STEP 2

Method validates the proposed change

savings.Deposit(5) passes the positive-amount check and increases balance from 10 to 15. Outside code cannot change the private field directly.

STEP 3

Check valid and invalid cases

GetBalance() returns 15. Deposit(-3) throws an exception before changing the balance. Encapsulation is controlled access, not merely writing private.

GUIDED PRACTICE

Trace a different validated account

Using the Account class, run Account current = new Account(20); current.Deposit(7); Then attempt current.Deposit(-2);. What does current.GetBalance() give afterwards if the exception is caught by the caller?

Example 1 of 2
YOUR TURN

Show the value after each operation

What happens at construction, after the valid deposit, and at the attempted negative deposit?

MODEL ANSWER

27; invalid deposit rejected

Constructor sets 20; valid deposit makes 27. The second call raises an ArgumentOutOfRangeException before the assignment; when the caller handles it, the balance remains 27.
