Recursion and algorithm tracing

  • Trace recursive calls downward before calculating values on return.
  • Name the base case and variable that progresses toward it.
  • Recursion depth consumes call-stack memory even when total time is linear.

NEW LEARNING · MODEL FIRST

Follow the trace

static int SumOdds(int n){
 if(n<=0)return 0;
 int add=(n%2==1)?n:0;
 return add+SumOdds(n-1);
}
// SumOdds(5)=5+3+1=9.

Outputs 321 on descent. Nothing prints for n0.

WE DO · DIFFERENT EXAMPLE

static void Count(int n){
 if(n==0)return;

 Console.Write(n);
}
STEP 1

Explain the result

QUESTION 1 OF 3 · FOUNDATION

Trace SumOdds(4), listing contributions and returned result. [6]

WORKED ANSWER / MARK SCHEME

Calls 4,3,2,1,0 [2], contributions 0,3,0,1 [2], base0 [1], result4 [1].

QUESTION 2 OF 3 · CORE

For F(n): if n=0 return, else print(n) then F(n-1), state F(4) output and why. [6]

WORKED ANSWER / MARK SCHEME

Print 4 [1],3 [1],2 [1],1 [1] on descent [1]; base0 prints nothing [1].

QUESTION 3 OF 3 · CHALLENGE

Write an iterative C# method to sum the positive odd integers up to n (n ≥ 0), matching SumOdds(n). Compare its time and auxiliary space with the recursive method. [6]

WORKED ANSWER / MARK SCHEME

Initialise sum=0 [1]; iterate odd values using for(int i=1;i<=n;i+=2) [2]; add each i to sum and return it [1]; both approaches take O(n) time [1]; iterative O(1) auxiliary memory versus O(n) recursive call stack [1].
