Debugging and error correction

By the end, you can…
  • Diagnose off-by-one errors with a trace
  • Correct an invalid array index
  • Fix a binary-search boundary update that fails to progress

Key vocabulary

off-by-one errorexceptiontracepreconditiontermination
NEW LEARNING · EXAMPLE FIRST

Predict the effect

int[] a={3,6,9};
for(int i=0; i<=a.Length; i++)
    Console.WriteLine(a[i]); // BUG
// FIX: i<a.Length
STEP 1 OF 3

Check valid indexes

A three-element array has valid indexes 0, 1 and 2.

STEP 2 OF 3

Follow the condition

When i is 3, i<=a.Length remains true and attempts to read a[3], causing an exception.

STEP 3 OF 3

Fix and retest

Use i<a.Length, which stops before i becomes an invalid index.

I DO · MODEL

Correct a loop summing [2,4] that uses <= length.

for(int i=0;i<=values.Length;i++)
  total+=values[i];
STEP 1 OF 2

Predict

The array's valid indexes are 0 and 1, not 2.

STEP 2 OF 2

Explain

Use i < values.Length and the total is 6.

WE DO · DIFFERENT GUIDED PROBLEM

Binary search uses low=mid when a[mid]<target. Why may it loop forever?

int mid=(low+high)/2;
if(a[mid]<target) low=mid;
STEP 1 OF 2

Predict

With low=3 and high=4, midpoint remains 3 and low=mid fails to shrink the interval.

STEP 2 OF 2

Explain

Use low=mid+1 to exclude the checked midpoint and guarantee progress.

Foundation · 1 OF 3

Fix the loop condition i<=a.Length when visiting every array item.

MODEL ANSWER

Change to i<a.Length.

Core · 2 OF 3

When a[mid]>target, what should binary search do to high?

MODEL ANSWER

Set high=mid-1 to remove the checked midpoint.

Stretch · 3 OF 3

Choose normal, boundary and erroneous indexes when a method accepts only indexes 0–4.

MODEL ANSWER

Normal index 2; boundary indexes 0 or 4; erroneous indexes −1 or 5, which must be rejected or handled.
