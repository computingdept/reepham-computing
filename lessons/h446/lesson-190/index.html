Programming constructs and scope

By the end, you can…
  • Identify sequence, selection and iteration
  • Distinguish local and class-level variables
  • Predict scope-dependent output

NEW LEARNING · CODE FIRST

Read the code; predict its effect

using System;
class Program
{
    static int score = 10;
    static void Show()
    {
        int score = 3; // local shadows field
        Console.WriteLine(score);
    }
    static void Main() { Show(); }
}
STEP 1 OF 3

Three control structures

Sequence runs in order; selection chooses a branch; iteration repeats instructions.

STEP 2 OF 3

Where is a variable visible?

A local declaration belongs to its block or method; a class-level field can be accessed by relevant class methods.

STEP 3 OF 3

Shadowing

A local variable with the same name as a field can hide that field inside the method; trace precisely which one is printed.

I DO · MODEL

A class field x is 8. A method declares int x=2 and prints x. What appears?

STEP 1 OF 2

Predict first

Which x is in scope at the print statement?

STEP 2 OF 2

Model solution

The method-local x is 2 and shadows the field. The program prints 2.

WE DO · GUIDED

A class field points is 20. A method runs points += 5 and prints points without declaring a local variable.

STEP 1 OF 2

Predict first

Which variable is modified?

STEP 2 OF 2

Model solution

The class field is modified to 25, then 25 is printed.

Foundation · 1 OF 3

Class field level = 9; method declares int level = 4 and prints level. What appears?

WORKED ANSWER

4, because the local level shadows the field.

Core · 2 OF 3

Class field attempts = 2; method executes attempts++; then prints attempts. What appears?

WORKED ANSWER

3, because no local attempts was declared, so the class field is incremented.

Stretch · 3 OF 3

Describe one risk of unnecessary global/class-level mutable variables.

WORKED ANSWER

Different methods can alter shared state unexpectedly, making dependencies, debugging and testing harder; prefer a local value or parameter where appropriate.

True or false?

A local variable always changes a same-named class field.

MODEL ANSWER

False. A local of the same name usually shadows the field, leaving the field unchanged.
