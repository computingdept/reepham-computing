Lesson 052 · Binary Search Trees with Node Objects

By the end you can…
  • A binary search tree (BST) keeps smaller keys in the left subtree and larger keys in the right subtree under a consistent duplicate-key policy.
  • Each node stores a key and optional Left/Right child references. Inserting begins at the root and follows comparisons until an empty child link is found.
  • Inorder traversal (left, root, right) prints sorted keys for a valid BST without duplicates.

I DO · MODEL

Insert key 7 into BST root 8, left 3, right 10, with 6 right of 3.

7<8 → left(3)
7>3 → right(6)
7>6 → right child of 6
WORKING

Explain the trace

7 becomes right child of 6; follow comparisons until a null child is reached.

WE DO · DIFFERENT PROBLEM

Insert 12 into a different BST: root 9, children 5 and 14.

12>9 → right(14)
12<14 → left child of 14
WORKING

Explain the trace

Place 12 as left child of 14. Tree ordering remains valid.

WORKED MODEL ANSWER

CORE · Q2/3

For BST with keys 8,3,10,6, give inorder traversal and explain sorting. [6]

WORKED MODEL ANSWER

3,6,8,10 [4]; left-root-right order follows BST invariant [2].

CHALLENGE · Q3/3

Explain why BST search may be O(log n) when balanced but O(n) when skewed. [6]

WORKED MODEL ANSWER

Balanced height ≈log n [2]; follow only one path per comparison [1]; sorted insertions may create chain height n [2]; search may inspect n nodes [1].
